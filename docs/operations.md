# 운영 가이드

방송을 실제로 돌릴 때 필요한 설정과 조정 지점을 정리한 문서다. 설치와 기본 실행 명령은 [README](../README.md)를 참고한다.

## 1. 포트와 주소

모든 서비스는 루프백(`127.0.0.1`)에 바인딩된다.

| 용도 | 주소 |
|---|---|
| Node API | `http://127.0.0.1:4310` |
| 방송 화면 (dev) | `http://127.0.0.1:4173` |
| 방송 화면, 입력창 숨김 (OBS 송출용) | `http://127.0.0.1:4173/?input=0` |
| 시청자 채팅 화면 | `http://127.0.0.1:4173/chat.html` |
| 방송 화면 빌드 프리뷰 | `http://127.0.0.1:4174` |
| 관리자 웹 렌더러 | `http://127.0.0.1:5174` |

API 포트는 `BORI_SERVER_PORT`, 관리자 렌더러 주소는 `BORI_ADMIN_URL`로 바꾼다.

관리자 Electron 창은 `npm run dev` 또는 `npm run dev:admin` 실행 시 함께 열린다.

방송 화면과 관리자 화면은 WebSocket이 아니라 폴링으로 상태를 받는다. 방송 화면과 채팅 화면은 1초, 관리자 화면은 1.5초 간격으로 `GET /api/state`를 호출하고 상태 필드의 변화를 비교해 반영한다.

### 휴대폰에서 채팅 화면 열기

`chat.html`을 휴대폰에서 열려면 Vite dev 서버를 LAN에 노출하고 로컬 머신의 LAN IP로 접속해야 한다.

**이 경로에는 인증이 전혀 없다.** 주소를 아는 누구나 채팅을 투입할 수 있으므로 신뢰할 수 있는 사설 네트워크에서만 사용한다. 공용 Wi-Fi나 포트 포워딩으로 외부에 여는 것은 권장하지 않는다.

## 2. LLM 설정

관리자 화면 **외부 LLM** 패널에서 업체와 모델을 고르고 API 키를 입력한다.

현재 지원 업체는 **OpenAI**와 **Anthropic** 2종이다. OpenAI는 Chat Completions에 Structured Outputs(`json_schema`, `strict: true`)를, Anthropic은 Messages API에 `tool_choice` 강제 도구 호출을 사용한다. 같은 JSON Schema를 서로 다른 방식으로 강제하므로 출력 검증 코드는 하나로 공유된다. `gemini`는 타입에만 존재하고 어댑터 팩토리가 없어 지원 업체 목록에서 자동으로 제외된다.

OpenAI는 실 API 환경에서 검증되었다. Anthropic 어댑터는 실 API 환경에서 검증되지 않았다.

스트리밍은 사용하지 않는다. 단발 `fetch` 호출에 `AbortController` 기반 8초 타임아웃을 건다. 실측 평균 지연은 1.5~2.5초다.

### 키 저장 위치와 암호화

화면으로 입력한 키는 `data/llm-config.json`에 저장되며 화면에 다시 표시되지 않는다. 어떤 GET 응답에도 키가 포함되지 않고 `hasApiKey` 불리언만 나간다.

저장 방식은 **AES-256-GCM**이고, 암호화 키는 사용자명과 호스트명을 재료로 `scryptSync`로 파생한다. 암호문에는 `enc.v1:` 접두사가 붙는다. 이전 버전에서 평문으로 저장된 파일을 읽으면 즉시 암호문으로 다시 저장하는 자동 마이그레이션이 동작한다.

위협 모델의 한계는 명확하다. 같은 머신에서 코드를 실행할 수 있는 주체는 복호화도 할 수 있다. 이 암호화는 설정 파일이 그대로 유출되거나 실수로 공유되는 상황을 막는 수준이며, 로컬 권한을 가진 공격자를 막지 못한다.

### 환경변수 대안

저장된 키가 없을 때만 환경변수가 사용된다.

```bash
export OPENAI_API_KEY='<키>'
npm run dev:server
```

Windows PowerShell에서는 다음과 같다.

```powershell
$env:OPENAI_API_KEY='<키>'
npm run dev:server
```

`.env.example`을 `.env`로 복사해 값을 채우는 방법도 동일하게 동작한다.

### 응답 라우팅 순서

```text
위험 주제 · 프롬프트 공격 패턴
 → LLM 호출 없이 차단. 무반응으로 넘어간다

기억을 묻는 패턴
 → 규칙을 건너뛰고 LLM으로 보낸다

인사 · 칭찬 · 위로 · 음악 · 게임
 → 규칙 문장 (규칙이 llmPreferred로 표시된 경우 LLM에 양보한다)

질문과 규칙에 없는 채팅
 → 관련 기억 주입 후 LLM 호출
 → 출력 검증 실패 또는 호출 실패 시 규칙 폴백 문장

LLM 비활성 · 키 없음 · 회로 개방 상태
 → 규칙 폴백 문장
```

LLM 출력은 6단계로 검증된다. JSON 파싱 → 응답 길이 → 감정 allowlist → intensity/duration 범위 → 모션 allowlist → layer/priority. 하나라도 실패하면 폴백 문장이 나간다.

회로 차단기는 연속 실패가 `failureThreshold`에 닿으면 열리고, `cooldownSeconds` 동안 LLM 호출을 차단한다. 이 사이에도 방송은 규칙 문장으로 끊김 없이 이어지며, 실패 내역은 관리자 화면에만 표시된다. 호출 수, 실패 수, 검증 실패 수, 평균 지연이 함께 기록된다.

### 업체 추가 방법

1. `packages/llm/src/`에 어댑터를 작성한다. 프롬프트를 받아 검증 가능한 JSON을 돌려주는 함수 하나면 된다.
2. `packages/llm/src/index.ts`의 `adapterFactories`에 한 줄로 등록한다.

`supportedProviders`는 팩토리가 `null`이 아닌 항목만 자동으로 노출하므로 별도 목록 수정이 필요 없다. 방송 로직은 어느 업체를 쓰는지 알지 못한다.

## 3. TTS 설정

관리자 화면 **음성 (TTS)** 패널에서 켠다. OpenAI TTS는 LLM과 같은 API 키를 사용하므로 키를 먼저 저장해야 한다.

| 항목 | 값 |
|---|---|
| 목소리 | alloy, echo, fable, onyx, nova, shimmer (기본값 nova) |
| 모델 | `tts-1` 빠름, `tts-1-hd` 고음질 |
| 속도 | 0.25 ~ 4.0 (기본값 1.0) |

설정은 `data/tts-config.json`에 저장된다.

**음성 합성은 서버에서만 수행한다.** 브라우저는 `GET /api/tts/{id}`로 mp3 바이너리만 받으므로 API 키가 클라이언트로 나가지 않는다. 합성된 음성은 서버 메모리에 최근 30건까지 삽입 순서(FIFO)로 캐시되며, 서버를 재시작하면 사라진다.

답변은 음성 합성이 끝난 뒤에 말풍선과 함께 표시된다. 소리와 자막을 맞추기 위한 선택이며, 그만큼 응답까지 1~2초가 더 걸린다.

### 소리가 나지 않을 때

브라우저가 사용자 상호작용 없는 자동 재생을 차단한 경우다. 방송 화면 위쪽의 **소리 켜기** 버튼을 한 번 누르면 이후로는 정상 재생된다. OBS 브라우저 소스에서는 자동 재생이 차단되지 않으므로 이 버튼이 필요 없다.

### 업체 추가 방법

`packages/llm/src/tts.ts`에 합성 함수를 만들고 `synthesizeSpeech`에 분기를 추가한다. 출력은 mp3로 통일한다. 방송 로직은 어느 업체를 쓰는지 알지 못한다.

### ElevenLabs를 쓰지 않는 이유

ElevenLabs 어댑터(`/text-to-speech`)는 구현되어 있으나 실 키로 검증되지 않았고 현재 사용하지 않는다. Voice Library에 한국어를 모국어로 녹음한 목소리가 많지 않아 애니메이션풍 한국어 캐릭터 목소리를 고르기 어렵다고 판단해 보류한 상태다.

OpenAI 목소리 6종은 모두 실제 사람 톤이고 한국어 발음이 자연스럽지 않은 편이라 캐릭터와 잘 맞지 않는다. 한국어 캐릭터 목소리 확보는 아직 해결되지 않은 과제이며, 다음 후보를 검토 대상으로 둔다.

| 후보 | 검토 사유 |
|---|---|
| 네이버 CLOVA Voice | 한국어 전용. 밝은 캐릭터 보이스가 있다 |
| Typecast | 한국 서비스. 캐릭터 음성에 특화되어 있다 |
| Supertone | 한국 서비스. 캐릭터 음성에 특화되어 있다 |
| 음성 클로닝 | 원하는 한국어 샘플로 목소리를 직접 만드는 방식 |

## 4. 장기 기억 설정

관리자 화면 **장기 기억** 패널에서 설정한다. 저장 위치는 `data/memories.json`이고 설정은 `data/memory-config.json`이다. 별도의 데이터베이스나 벡터DB를 쓰지 않는다.

| 항목 | 설정 키 | 기본값 | 의미 |
|---|---|---|---|
| 사용 여부 | `enabled` | `true` | 끄면 기억을 저장하지도 검색하지도 않는다 |
| 전달 개수 | `maxMemories` | 5 | LLM 프롬프트에 넣을 최대 기억 수 |
| 최소 유사도 | `minSimilarity` | 0.3 | 이 값 아래는 관련 없다고 본다. 낮게 두면 관련 기억을 놓칠 확률이 줄지만 잡음이 늘어난다 |
| 보관 기간 | `retentionDays` | 30 | 저장한 기억의 기본 수명(일). 지나면 자동 만료된다 |
| 임베딩 모델 | `embeddingModel` | `text-embedding-3-small` | 1536차원 |

검색은 코사인 유사도를 직접 계산해 `유사도 + 중요도 × 0.05`로 점수를 매기고, `minSimilarity` 필터를 통과한 상위 K개를 프롬프트에 넣는다. 임베딩 키가 없거나 임베딩 호출이 실패하면 예외를 던지지 않고 중요도·최신순 정렬로 자동 강등된다. 저장 시 임베딩 실패도 저장 자체를 막지 않는다.

같은 문장이 다시 등장하면 `repeatCount`가 올라가고 중요도가 0.1 증가하며 수명이 연장된다.

### 기억 관리

관리자 화면에서 다음 작업을 수행한다.

- **목록 조회** — 최근 50건을 확인한다 (`GET /api/memory`)
- **개별 삭제** — 항목 단위로 지운다 (`DELETE /api/memory/{id}`)
- **전체 삭제** — 저장된 기억을 모두 지운다 (`DELETE /api/memory/all`)

기억은 시청자 식별자와 함께 저장되지만 **검색에는 시청자 필터가 적용되지 않는다.** 여러 사람이 채팅하면 다른 시청자의 기억이 검색 결과에 섞일 수 있다. 여러 시청자를 대상으로 운영할 때는 이 점을 감안하고, 필요하면 전체 삭제로 초기화한다.

## 5. OBS 송출

### 준비

OBS에서 **도구 > WebSocket 서버 설정**을 켜고 비밀번호를 확인한다. 비밀번호는 환경변수로만 전달하며 코드나 설정 파일에 적지 않는다.

```powershell
$env:OBS_PASSWORD='<OBS WebSocket 비밀번호>'
node tools/obs/setup.mjs
```

macOS/Linux에서는 다음과 같다.

```bash
export OBS_PASSWORD='<OBS WebSocket 비밀번호>'
node tools/obs/setup.mjs
```

OBS WebSocket 주소는 `OBS_URL`로 지정하며 기본값은 `ws://127.0.0.1:4455`다. 클라이언트(`tools/obs/client.mjs`)는 op0 Hello의 salt/challenge SHA256 인증 핸드셰이크와 requestId 기반 Promise 매칭을 외부 라이브러리 없이 직접 구현한 것이다.

### 두 스크립트가 하는 일

**`tools/obs/setup.mjs`** — 송출 환경을 만든다.

1. 캔버스 해상도를 확인해 1920x1080이 아니면 변경한다.
2. 씬이 없으면 생성한다 (기본 이름 `보리 방송`, `BORI_OBS_SCENE`으로 변경).
3. 브라우저 소스를 생성하거나, 이미 있으면 설정만 갱신한다 (기본 이름 `보리 방송 화면`, `BORI_OBS_SOURCE`로 변경). 방송 중 소스가 꺼지지 않도록 `shutdown: false`, 활성화 시 새로고침하도록 `restart_when_active: true`, 오디오를 OBS로 넘기도록 `reroute_audio: true`를 설정한다.
4. 해당 씬을 현재 프로그램 씬으로 전환한다.
5. 이전 캔버스 기준으로 남아 있던 변환을 초기화해 소스를 캔버스에 정확히 맞춘다.

**`tools/obs/screenshot.mjs`** — 현재 씬을 폭 1280px PNG로 저장한다. 송출 화면이 실제로 어떻게 나가는지 눈으로 확인할 때 사용한다. 대상은 `OBS_SHOT_SOURCE`, 저장 경로는 `OBS_SHOT_PATH`로 지정하며 기본값은 각각 `보리 방송`, `./obs-shot.png`다.

### `?input=0`을 붙이는 이유

방송 화면에는 채팅을 직접 넣을 수 있는 입력창이 있다. 이 입력창이 송출 화면에 그대로 나가면 시청자에게 보이므로, 브라우저 소스가 여는 URL에는 `?input=0`을 붙여 입력창을 숨긴다.

브라우저 소스가 열 주소는 `BORI_URL`로 지정하며 기본값은 `http://127.0.0.1:4174/?input=0`이다. dev 서버를 송출하려면 `BORI_URL='http://127.0.0.1:4173/?input=0'`으로 지정한다.

채팅 투입은 입력창이 보이는 `http://127.0.0.1:4173`이나 별도 채팅 화면, 관리자 앱에서 한다.

## 6. 튜닝 파라미터 레퍼런스

### 모델 구도

구도는 Cubism SDK 샘플의 `lappdefine.ts` 상수로 조정한다.

```text
<Cubism SDK 샘플>/src/lappdefine.ts
```

| 상수 | 현재 값 | 의미 |
|---|---|---|
| `ModelScale` | 2.0 | 값이 클수록 확대된다 |
| `ModelOffsetX` | 0.0 | 화면 정중앙. 음수면 왼쪽으로 이동한다 |
| `ModelOffsetY` | -0.52 | 음수면 아래로 내려가 머리가 화면 위쪽에 온다 |

화면 중앙이 `(0, 0)`이고 위쪽이 `+Y`다. 실제 적용은 `lapplive2dmanager.ts`의 `onUpdate()`에서 projection에 곱하는 지점이다.

### 화면 레이아웃

`apps/broadcast/src/styles.css`의 CSS 변수로 조정한다.

| 변수 | 의미 |
|---|---|
| `--chat-panel-width` | 우측 채팅 패널의 폭 |
| `--stage-padding` | 무대 영역의 바깥 여백 |
| `--stage-gap` | 무대와 채팅 패널 사이 간격 |

말풍선은 모델과 마찬가지로 화면 중앙 기준으로 배치된다.

배경은 현재 보라색 그라데이션이 하드코딩되어 있다. OBS 오버레이로 쓰려면 `.broadcast-shell`의 배경을 투명하게 바꿔야 한다.

### 시선과 립싱크

`apps/broadcast/src/main.tsx` 상단의 상수로 조정한다.

| 상수 | 의미 |
|---|---|
| `GAZE.lookChance` | 새 채팅을 쳐다볼 확률. 0.6이면 열 번에 여섯 번 본다 |
| `GAZE.chatXMin` / `GAZE.chatXMax` | 쳐다볼 때 고개를 돌리는 정도의 범위 |
| `GAZE.holdMinMs` / `GAZE.holdMaxMs` | 채팅을 보고 있는 시간 |
| `GAZE.idleIntervalMinMs` / `GAZE.idleIntervalMaxMs` | 평소 둘러보는 간격. 길게 두면 한곳을 응시하는 것처럼 보인다 |
| `GAZE_SPEED` | 고개가 돌아가는 속도(1/초). 작으면 느리게 돌고, 너무 작으면 다 돌아보기 전에 시선이 되돌아온다 |
| `LIP_SYNC.audioSmoothing` | 입 움직임의 떨림을 누른다. 작을수록 부드럽다 |
| `LIP_SYNC.msPerChar` | 한 글자를 말하는 시간. 말 속도를 정한다 |
| `LIP_SYNC.cycleMs` | 입이 열리고 닫히는 주기 |
| `LIP_SYNC.openMax` | 최대로 벌리는 정도 (음성이 없을 때) |
| `LIP_SYNC.audioGain` | 음성 파형을 입 벌림으로 바꾸는 배율. 입이 작게 벌어지면 값을 올린다 |

시선 보간은 `ratio = 1 - exp(-2.5 × deltaSeconds)` 지수 감쇠를 쓰므로 60Hz와 144Hz에서 동일한 속도로 움직인다.

립싱크는 2종이다. 음성이 있으면 WebAudio `AnalyserNode`의 RMS를 입 벌림에 매핑하고, 음성이 없으면 글자수 × 78ms 길이의 사인파에 jitter를 더한다. 이 모델은 `ParamMouthOpenY` 하나만 립싱크 대상으로 등록되어 있어 모음별 입 모양은 구분되지 않는다.

## 7. 표정과 모션의 짝 구조

이 모델은 **표정 파일이 효과를 켜는 스위치이고, 모션 파일이 그 효과의 애니메이션을 돌리는 짝 구조**다.

| 이름 | 표시 이름 | 표정 파라미터 | 모션 파라미터 |
|---|---|---|---|
| `xingxingyan` | 반짝이는 눈 | Param56 | Param58 |
| `kuqi` | 울음 | Param57 | Param59 |
| `shengqi` | 화남 | Param66 | Param68 |
| `shoushi` | 게임패드 | Param69 | Param70 |
| `shangxin` | 슬픔 | Param63 | 없음 |
| `chidai` | 멍함 | Param60 | 없음 |
| `wuyu` | 어이없음 | Param61 | 없음 |
| `changfa` | 긴 머리 | Param55 | 없음 |

**표정 없이 모션만 실행하면 화면에 아무 변화가 없다.** 모션을 실행할 때는 반드시 같은 이름의 표정을 함께 켠다. 기본 상태는 표정 해제다. `changfa`는 헤어스타일을 바꾸는 표정이라 기본 상태로 쓰지 않으며, 감정 매핑에 연결되어 있지 않아 관리자 테스트 버튼으로만 실행된다.

### 두 파일의 실제 차이

`shengqi`로 파라미터 값을 0.5초 간격으로 측정한 결과다.

| 실행 내용 | Param66 (표정) | Param68 (모션) |
|---|---|---|
| 표정만 | 1 고정 | 0.204 고정 |
| 표정 + 모션 | 1 고정 | 0.589 → 0.238 → 0.898 → 0.600 → 0.287 → 0.953 |

표정은 효과를 켠 채로 멈춘 상태를 만들고, 모션은 그 효과 안에서 값을 계속 흔든다. `shengqi`의 경우 표정만 실행하면 김이 한 위치에 멈춰 있고, 모션까지 실행해야 김이 계속 뿜어져 나온다.

**정지 이미지로는 둘을 구분할 수 없다.** 스크린샷 비교로 판단하지 말고 시간축에 따른 파라미터 변화로 확인한다.

이 모델의 모션 4개는 모두 짝 표정이 필요한 효과 애니메이션이라 대기 모션으로 쓸 수 없다. 대기 중의 눈 깜빡임과 호흡은 SDK가 처리한다.

표시 이름 중 `shengqi`, `shoushi`, `changfa`만 화면으로 확인되었다. `kuqi`, `shangxin`, `wuyu`, `chidai`, `xingxingyan`의 한국어 표시 이름은 파일 이름을 번역한 잠정값이다.

## 8. 개발 환경 주의사항 (Windows)

`npm run dev:server`를 중단할 때 npm 래퍼 프로세스만 종료되고 실제 node 프로세스가 남아 포트를 계속 점유하는 경우가 있다. 이 상태에서 서버를 다시 띄우면 `EADDRINUSE`로 실패한다. 서버는 1초 간격 최대 10회 재시도로 이 상황을 흡수하지만, 이전 프로세스가 끝내 종료되지 않으면 직접 확인해야 한다.

PowerShell에서 포트를 점유한 프로세스를 확인한다.

```powershell
Get-NetTCPConnection -LocalPort 4310 -State Listen | Select-Object OwningProcess
```

macOS/Linux에서는 다음과 같다.

```bash
lsof -i :4310
```

관리자 화면에서 방송 시작 버튼이 반응하지 않으면 API 서버가 떠 있는지부터 확인한다. Vite dev 프록시는 백엔드가 죽어 있어도 5xx 응답을 돌려주므로 `fetch` 예외만으로는 서버 다운을 판단할 수 없다. 상태 코드가 500 이상인지 함께 확인해야 한다.
