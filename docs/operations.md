# 운영 가이드

이터널리턴 메타 대시보드를 실제로 돌릴 때 필요한 설정과 조정 지점을 정리한 문서다. 설치와 기본 실행 명령은 [README](../README.md)를 참고한다.

> 2026-11-21 방송·1:1 대화를 지우면서 OBS 송출, 채팅 화면, 장기 기억, 응답 라우팅 절을 지웠다(ADR-028). 예전 내용은 git 기록에 있다.

## 1. 포트와 주소

모든 서비스는 루프백(`127.0.0.1`)에 바인딩된다.

| 용도 | 주소 |
|---|---|
| Node API, 빌드한 화면(`/companion/`, `/studio/`) | `http://127.0.0.1:4310` |
| 대시보드 화면 (dev) | `http://127.0.0.1:4175/companion/` |
| 대시보드 화면 빌드 프리뷰 | `http://127.0.0.1:4176/companion/` |
| 스튜디오 웹 렌더러 (dev) | `http://127.0.0.1:5174/studio/` |

API 포트는 `BORI_SERVER_PORT`, 스튜디오 렌더러 주소는 `BORI_ADMIN_URL`로 바꾼다. 화면은 WebSocket이 아니라 폴링으로 상태를 받는다.

### 허용 Origin

서버는 브라우저 요청의 Origin을 허용 목록으로 검사한다. 목록 밖 Origin은 403, 루프백이 아닌 Host는 421이다. 근거는 [ADR-015](./decisions.md)에 있다.

기본 허용 목록은 아래 포트의 `http://127.0.0.1:{포트}`와 `http://localhost:{포트}`, 그리고 서버 자신의 주소다.

| 포트 | 클라이언트 |
|---|---|
| 4175 | 대시보드 화면 (dev) |
| 4176 | 대시보드 화면 빌드 프리뷰 |
| 5174 | 스튜디오 렌더러 (dev) |

방송 화면 포트(4173·4174)는 방송 화면과 함께 지웠다. 다른 주소에서 여는 클라이언트는 `BORI_ALLOWED_ORIGINS`에 쉼표로 덧붙인다. 형식이 잘못된 항목은 서버가 기동할 때 경고를 남기고 무시한다.

Origin이 없는 요청(curl, 통합 검사)은 Origin 검사를 받지 않는다. 본문이 있는 POST·PATCH·PUT은 `Content-Type: application/json`이어야 하고(아니면 415), 본문은 64KB를 넘을 수 없다(413).

## 2. LLM 설정

스튜디오 설정 탭 **외부 LLM** 패널에서 업체와 모델을 고르고 API 키를 입력한다. LLM은 보리가 읽을 메타 분석 대사를 쓰는 데만 쓴다. 꺼져 있거나 실패하면 정해진 문장으로 읽는다.

현재 지원 업체는 **OpenAI**와 **Anthropic** 2종이다. OpenAI는 Chat Completions에 Structured Outputs(`json_schema`, `strict: true`)를, Anthropic은 Messages API에 `tool_choice` 강제 도구 호출을 사용한다. 같은 JSON Schema를 서로 다른 방식으로 강제하므로 부르는 쪽의 결과 검사(`parse`) 코드는 하나다. `gemini`는 타입에만 존재하고 어댑터 팩토리가 없어 지원 업체 목록에서 자동으로 제외된다.

OpenAI는 실 API 환경에서 검증되었다. Anthropic 어댑터는 실 API 환경에서 검증되지 않았다.

스트리밍은 사용하지 않는다. 단발 `fetch` 호출에 `AbortController` 기반 타임아웃(설정 `timeoutMs`, 기본 8초)을 건다.

### 키 저장 위치와 암호화

화면으로 입력한 키는 `data/llm-config.json`에 저장되며 화면에 다시 표시되지 않는다. 어떤 GET 응답에도 키가 포함되지 않고 `hasApiKey` 불리언만 나간다.

저장 방식은 **AES-256-GCM**이고, 암호화 키는 사용자명과 호스트명을 재료로 `scryptSync`로 파생한다. 암호문에는 `enc.v1:` 접두사가 붙는다. 이전 버전에서 평문으로 저장된 파일을 읽으면 즉시 암호문으로 다시 저장하는 자동 마이그레이션이 동작한다.

위협 모델의 한계는 명확하다. 같은 머신에서 코드를 실행할 수 있는 주체는 복호화도 할 수 있다. 이 암호화는 설정 파일이 그대로 유출되거나 실수로 공유되는 상황을 막는 수준이며, 로컬 권한을 가진 공격자를 막지 못한다.

### 환경변수 대안

저장된 키가 없을 때만 환경변수가 사용된다.

```bash
export OPENAI_API_KEY='<키>'
npm run dev:server
```

Windows PowerShell에서는 다음과 같다.

```powershell
$env:OPENAI_API_KEY='<키>'
npm run dev:server
```

`.env.example`을 `.env`로 복사해 값을 채우는 방법도 동일하게 동작한다.

### 회로 차단기

`createLlmClient().complete<T>(settings, apiKey, request, parse)`는 꺼짐·키 없음·회로 열림이면 업체를 부르지 않는다. 업체 호출 실패와 `parse` 거부가 연속으로 `failureThreshold`번 쌓이면 회로가 열려 `cooldownSeconds` 동안 부르지 않는다. 429(속도 제한)는 Retry-After를 지켜 한 번 다시 보내고, 그래도 남으면 실패로만 세고 회로를 열 연속 실패로는 세지 않는다. 호출 수·실패 수·검증 실패 수·평균 지연은 스튜디오 설정 탭에 보인다.

### 지운 설정 칸

1:1 대화를 쓰던 때의 `rollingSummaryEnabled`·`rollingSummaryTurns`·`macroEnabled`는 지웠다. 예전 `data/llm-config.json`에 남아 있어도 경고·백업 없이 무시하고, 다음 저장 때 파일에서 빠진다.

### 업체 추가 방법

1. `packages/llm/src/`에 어댑터를 작성한다. `LlmRequest`(시스템·사용자 프롬프트, 스키마, 시간 상한)를 받아 JSON 문자열을 돌려주는 함수 하나면 된다.
2. `packages/llm/src/index.ts`의 `adapterFactories`에 한 줄로 등록한다.

`supportedProviders`는 팩토리가 `null`이 아닌 항목만 자동으로 노출한다.

## 3. TTS 설정

스튜디오 설정 탭 **음성 (TTS)** 패널에서 업체(Fish Audio·ElevenLabs·OpenAI)를 고르고 켠다. OpenAI TTS는 LLM과 같은 API 키를, Fish Audio는 `.env`의 `FISH_API_KEY`를, ElevenLabs는 화면에서 넣은 키를 쓴다. 아래 표는 OpenAI 값이다.

| 항목 | 값 |
|---|---|
| 목소리 | alloy, echo, fable, onyx, nova, shimmer (기본값 nova) |
| 모델 | `tts-1` 빠름, `tts-1-hd` 고음질 |
| 속도 | 0.25 ~ 4.0 (기본값 1.0) |

설정은 `data/tts-config.json`에 저장된다.

**음성 합성은 서버에서만 수행한다.** 브라우저는 `GET /api/tts/{id}`로 mp3 바이너리만 받으므로 API 키가 클라이언트로 나가지 않는다. 합성된 음성은 서버 메모리에 최근 30건까지 삽입 순서(FIFO)로 캐시되며, 서버를 재시작하면 사라진다.

합성에 실패한 줄은 자막만 보인다.

### 소리가 나지 않을 때

브라우저가 사용자 상호작용 없는 자동 재생을 차단한 경우일 수 있다. 대시보드에서 한 번 누르고(예: 다시 듣기) 다시 확인한다. 설정 탭의 "합성 실패" 횟수와 마지막 오류도 본다.

### 업체 추가 방법

`packages/llm/src/tts.ts`에 합성 함수를 만들고 `synthesizeSpeech`에 분기를 추가한다. 출력은 mp3로 통일한다. 부르는 쪽은 어느 업체를 쓰는지 알지 못한다.

### 목소리

설계상 기본 목소리는 Fish Audio에 만든 "보리 목소리"다. 다만 코드의 기본값은 아직 OpenAI(꺼짐)라, 처음에는 설정 탭에서 업체와 목소리를 골라야 한다.

## 4. 이터널리턴 데이터

| 항목 | 값 |
|---|---|
| 키 | `.env`의 `ER_API_KEY`(화면 입력 없음). 없으면 갱신과 내 전적 조회를 하지 않는다 |
| 표본 | 상위 랭커 `BORI_ER_RANKERS`(기본 100)명 × 랭커마다 최근 랭크 경기 `BORI_ER_GAMES_PER_RANKER`(기본 10)판 |
| 걸리는 시간 | 개인 키는 초당 1회라 기본 규모는 몇 분(설계 추정 최대 약 22분) |
| 수동 갱신 | 스튜디오 설정 탭 "데이터 갱신" 또는 `POST /api/er/refresh` → `{ started }` |
| 자동 갱신 | 대시보드가 `GET /api/dashboard`를 부를 때 서버가 판정한다. 데이터가 없거나, 마지막 수집이 24시간 넘게 지났거나, 시즌이 바뀌었으면 시작한다. 하루에 한 번만 판정한다 |
| 상태 | `GET /api/dashboard`(또는 가벼운 `GET /api/dashboard/status`)의 `connection`(ready·stale·missing·refreshing)과 `refresh`(갱신할 수 있는지·진행 중 여부·진행률·마지막 오류·자동 시작 여부) |
| 파일 | `data/er-snapshot.json`(사전·최신 집계의 단일 원자 스냅샷; 파일이 없으면 예전 `er-dictionary.json`·`er-meta.json`을 읽어 이어 씀), `data/er-history/`(갱신마다, 최근 10개), `data/dashboard-settings.json`(게임 닉네임), `data/narration.json`(마지막 보리 대사) |

### 대시보드 라우트

| 메서드 | 경로 | 내용 |
|---|---|---|
| GET | `/api/dashboard` | 대시보드 상태(`DashboardState`). 필요하면 자동 갱신을 시작한다 |
| GET | `/api/dashboard/status` | 연결·갱신·기준만. 자동 갱신 판정과 조합 계산을 하지 않는다(스튜디오 설정 탭이 3초마다 묻는다) |
| POST | `/api/er/refresh` | 갱신 시작. `{ started }`. 이미 갱신 중이거나 `ER_API_KEY`가 없으면 false |
| GET / PUT | `/api/dashboard/settings` | `{ nickname }`. PUT하면 제어문자·방향 바꿈 문자·개행을 지우고 정리한 뒤(32자까지, 넘으면 400) 저장하고 전적을 다시 조회한다 |
| POST | `/api/narration/replay` | 다시 듣기. 마지막 대사를 `{ narration }`으로 돌려준다(없으면 404) |

갱신이 끝나면 서버가 사실 목록을 만들어 보리 대사를 쓰고 음성을 준비한다. LLM 키가 없거나 실패하면 정해진 문장으로, TTS가 실패한 줄은 자막만 나온다. 게임 닉네임은 화면에만 보이고 로그·LLM 사실 목록에는 넣지 않는다.

갱신은 이번 시즌 랭크 경기만 센다. 갱신에 실패하면 지난 파일을 그대로 쓰고 마지막 오류만 남긴다. 경기 하나·랭커 하나의 실패는 건너뛰고 계속한다. 확인용으로 짧게 돌릴 때는 `BORI_DATA_DIR`를 임시 폴더로 하고 랭커 수와 경기 수를 작게 준다.

## 5. 튜닝 파라미터 레퍼런스

### 모델 구도

구도는 Cubism SDK 샘플의 `lappdefine.ts` 상수로 조정한다.

```text
<Cubism SDK 샘플>/src/lappdefine.ts
```

| 상수 | 현재 값 | 의미 |
|---|---|---|
| `ModelScale` | 2.0 | 값이 클수록 확대된다 |
| `ModelOffsetX` | 0.0 | 화면 정중앙. 음수면 왼쪽으로 이동한다 |
| `ModelOffsetY` | -0.52 | 음수면 아래로 내려가 머리가 화면 위쪽에 온다 |

화면 중앙이 `(0, 0)`이고 위쪽이 `+Y`다. 실제 적용은 `lapplive2dmanager.ts`의 `onUpdate()`에서 projection에 곱하는 지점이다.

대시보드의 시선·립싱크 값은 `apps/companion/src/live2d/`에 있다. 예전 방송 화면(`apps/broadcast`)의 레이아웃·시선 상수표는 방송 화면과 함께 지웠다.

## 6. 표정과 모션의 짝 구조

이 모델은 **표정 파일이 효과를 켜는 스위치이고, 모션 파일이 그 효과의 애니메이션을 돌리는 짝 구조**다.

| 이름 | 표시 이름 | 표정 파라미터 | 모션 파라미터 |
|---|---|---|---|
| `xingxingyan` | 반짝이는 눈 | Param56 | Param58 |
| `kuqi` | 울음 | Param57 | Param59 |
| `shengqi` | 화남 | Param66 | Param68 |
| `shoushi` | 게임패드 | Param69 | Param70 |
| `shangxin` | 슬픔 | Param63 | 없음 |
| `chidai` | 멍함 | Param60 | 없음 |
| `wuyu` | 어이없음 | Param61 | 없음 |
| `changfa` | 긴 머리 | Param55 | 없음 |

**표정 없이 모션만 실행하면 화면에 아무 변화가 없다.** 모션을 실행할 때는 반드시 같은 이름의 표정을 함께 켠다. 기본 상태는 표정 해제다. `changfa`는 헤어스타일을 바꾸는 표정이라 기본 상태로 쓰지 않으며, 감정 매핑에 연결되어 있지 않다.

### 두 파일의 실제 차이

`shengqi`로 파라미터 값을 0.5초 간격으로 측정한 결과다.

| 실행 내용 | Param66 (표정) | Param68 (모션) |
|---|---|---|
| 표정만 | 1 고정 | 0.204 고정 |
| 표정 + 모션 | 1 고정 | 0.589 → 0.238 → 0.898 → 0.600 → 0.287 → 0.953 |

표정은 효과를 켠 채로 멈춘 상태를 만들고, 모션은 그 효과 안에서 값을 계속 흔든다. `shengqi`의 경우 표정만 실행하면 김이 한 위치에 멈춰 있고, 모션까지 실행해야 김이 계속 뿜어져 나온다.

**정지 이미지로는 둘을 구분할 수 없다.** 스크린샷 비교로 판단하지 말고 시간축에 따른 파라미터 변화로 확인한다.

이 모델의 모션 4개는 모두 짝 표정이 필요한 효과 애니메이션이라 대기 모션으로 쓸 수 없다. 대기 중의 눈 깜빡임과 호흡은 SDK가 처리한다.

표시 이름 중 `shengqi`, `shoushi`, `changfa`만 화면으로 확인되었다. `kuqi`, `shangxin`, `wuyu`, `chidai`, `xingxingyan`의 한국어 표시 이름은 파일 이름을 번역한 잠정값이다.

## 7. 개발 환경 주의사항 (Windows)

`npm run dev:server`를 중단할 때 npm 래퍼 프로세스만 종료되고 실제 node 프로세스가 남아 포트를 계속 점유하는 경우가 있다. 이 상태에서 서버를 다시 띄우면 `EADDRINUSE`로 실패한다. 서버는 1초 간격 최대 10회 재시도로 이 상황을 흡수하지만, 이전 프로세스가 끝내 종료되지 않으면 직접 확인해야 한다.

PowerShell에서 포트를 점유한 프로세스를 확인한다.

```powershell
Get-NetTCPConnection -LocalPort 4310 -State Listen | Select-Object OwningProcess
```

macOS/Linux에서는 다음과 같다.

```bash
lsof -i :4310
```

스튜디오 버튼이 반응하지 않으면 API 서버가 떠 있는지부터 확인한다. Vite dev 프록시는 백엔드가 죽어 있어도 5xx 응답을 돌려주므로 `fetch` 예외만으로는 서버 다운을 판단할 수 없다. 상태 코드가 500 이상인지 함께 확인해야 한다.

### 표본 확대와 갱신 예상 시간

기본 100명 × 최근 10판이며 환경변수로 줄이거나 늘릴 수 있다. 진행률 5%부터 경과 시간에 따른 대략적인 남은 분을 표시한다. 중복 경기와 요청 지연에 따라 추정치는 달라질 수 있다.
경기 상세는 `collectMeta`의 경기별 루프 안에서 집계하고 버린다. 메모리에는 중복 제거용 경기 ID(기본 최대 1,000개)와 조합·장비·특성별 카운트가 남고, 스냅샷과 최근 10개 이력에는 상세 응답 없이 집계만 저장한다. 파일 크기는 참가자 수에 정비례하지 않는다. 실제 10판 수집의 최대 메모리와 파일 크기는 이번 가짜 API 검사로 측정하지 않았다.

WebGL 연결이 끊기면 캐릭터 캔버스를 숨기고 복구 안내를 표시한다. 10초 안에 연결이 복구되면 모델을 새로 불러오며, 시간 초과 시 캐릭터 표시 불가 안내를 유지한다. 자막과 음성은 계속 사용할 수 있다.

## API 키 백업과 복구 (enc.v2)

Windows의 API 키는 DPAPI CurrentUser로 보호한 무작위 마스터 키(`data/secret-master.v2`)와 설정 파일(`llm-config.json`, `tts-config.json`)이 함께 있어야 복호화된다. 서버를 종료한 뒤 이 세 파일을 함께 백업한다. v1을 처음 읽을 때는 설정 파일의 원본을 같은 폴더의 `*.v1-backup-<시각>.json`에 남긴 뒤 v2로 이전한다. 이 백업에는 예전 방식으로 복호화할 수 있는 키가 있으므로 공유하지 않는다.

같은 PC·Windows 계정으로 복구할 때 서버를 종료하고 같은 시점의 마스터 파일과 설정 파일을 함께 복구한다. 다른 PC나 다른 Windows 계정으로 옮기면 키를 다시 입력해야 한다. DPAPI 사용자 프로필을 잃은 경우도 같다. 마스터 파일만 삭제하면 기존 v2 값이 풀리지 않으므로 삭제해서 오류를 우회하지 않는다.

마스터 파일이 없거나 손상된 경우 서버는 오류를 알리고 기존 값을 보존한다. 우선 백업 복구를 시도한다. 복구할 수 없으면 서버를 종료하고 세 파일을 별도 안전한 위치에 보관한 뒤, 설정 파일의 `apiKey`·`elevenLabsApiKey` 필드만 제거하고 손상 마스터 파일을 별도 보관 위치로 옮긴다. 다시 시작하면 v2 값이 없을 때만 새 마스터 키가 생성되며 설정 화면에서 키를 다시 입력할 수 있다. 설정의 다른 필드는 유지한다. 풀리지 않는 v1도 자동 삭제하지 않는다.

Linux/macOS는 OS 보호 없이 마스터 파일을 0600으로 저장한다. 이 파일과 설정이 함께 유출되면 키를 풀 수 있다. 비Windows 백업도 접근 권한을 제한한다. OS 보호기/쓰기 실패 오류에는 키나 PowerShell의 원문 출력이 포함되지 않는다.

자동 이전 백업은 기존 보관 정책에 따라 30일이 지나면 서버 시작 시 삭제된다. 장기 복구용 사본은 `data/` 밖의 접근이 제한된 위치에 별도로 보관한다.
