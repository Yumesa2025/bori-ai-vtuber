Overview

무엇을 만들었나

한 대의 로컬 머신에서 전부 돌아가는 AI 버추얼 스트리머다. 서버, 방송 화면, 관리자 앱이 모두 127.0.0.1에서 동작하며 외부 호스팅이나 클라우드 인프라를 쓰지 않는다. 시청자 채팅이 들어오면 아래 파이프라인을 거쳐 답변과 연출이 만들어진다.

채팅 수집→ 안전성 차단→ 규칙 / LLM / 폴백→ 출력 검증→ 음성 합성→ 표정 · 모션 · 립싱크→ OBS 송출
  • 답변이 끊기지 않는다. 규칙 → LLM → 폴백 문장의 3단 구조이고, LLM이 연속 실패하면 회로 차단기가 열려 호출을 끊는다. 그동안에도 방송은 규칙 문장으로 이어진다.
  • 말하면서 표정과 모션이 바뀐다. LLM이 답변과 함께 감정·모션을 고르지만, 허용 목록을 통과한 것만 화면에서 실행된다.
  • 목소리에 맞춰 입이 움직인다. 음성 파형의 실효값을 읽어 입 벌림에 반영하고, 음성이 없으면 글자 수 기반 립싱크로 자동 전환된다.
  • 시선이 살아 있다. 평소에는 1.1~3.2초마다 주위를 둘러보고, 새 채팅에는 60% 확률로만 반응한다. 매번 쳐다보면 오히려 어색하기 때문이다.
  • 지난 방송을 기억한다. 대화에서 취향·경험을 뽑아 장기 기억으로 저장하고, 이후 관련 질문이 오면 그 기억을 참고해 답한다.
  • 관리자 앱에서 통제한다. 세션 시작·종료, LLM·TTS·기억 설정, 표정·모션 즉시 테스트, 호출 통계와 실패 내역을 한 화면에서 다룬다.

Engineering

구현에서 어려웠던 것

각 항목의 상세한 근거와 트레이드오프는 설계 문서에 정리했다.

세션 세대 기반 비동기 경합 제어

LLM과 음성 합성이 비동기라, 응답이 도착하기 전에 방송이 종료·재시작되면 이전 방송의 답변이 새 화면에 나왔다. 방송 상태 플래그만으로는 "종료 후 재시작"을 구분할 수 없다. 호출 시점의 세대 번호를 캡처해 두고 콜백에서 세대가 다르면 결과를 폐기하도록 해결했다.

apps/server/src/index.ts

LLM 출력을 신뢰하지 않는 검증 계층

동일한 JSON Schema 하나를 OpenAI는 Structured Outputs로, Anthropic은 강제 도구 호출로 감싼다. 프로바이더가 달라도 검증 코드는 하나다. 구조화 출력은 형식만 보장하므로, 감정·모션 이름은 허용 목록을 통과해야만 실행되고 서버가 API 경계에서 한 번 더 강제한다.

packages/llm/src/validate.ts

SDK 내부 파이프라인에 개입한 립싱크

WebAudio로 계산한 파형 실효값을 입 벌림에 매핑하고 지수 평활로 떨림을 제거했다. 파라미터를 그냥 설정하면 Cubism SDK가 매 프레임 덮어쓰기 때문에, SDK 업데이트 순서를 분석해 정확한 지점에 주입 코드를 삽입해야 했다.

apps/broadcast/src/main.tsx

프레임레이트 독립 시선 보간

지수 감쇠 보간으로 60Hz든 144Hz든 같은 속도로 시선이 움직인다. 그 위에 확률적 반응, 응시 시간 랜덤화, 정면 복귀 대신 둘러보기 흐름으로 이어가기 같은 연출 규칙을 파라미터로 얹어 인형처럼 보이는 문제를 풀었다.

apps/broadcast/src/main.tsx

우아하게 성능이 저하되는 기억 검색

벡터DB 없이 코사인 유사도를 직접 구현하고 중요도를 가중치로 반영했다. 임베딩 키가 없거나 호출이 실패해도 예외로 중단되지 않고 중요도·최신순 정렬로 자동 강등된다. 저장 시 임베딩 실패도 저장 자체를 막지 않는다.

packages/memory/src/store.ts

라이선스 제약을 빌드 파이프라인으로 해결

구매한 상용 Live2D 모델과 Cubism SDK는 재배포가 금지되어 저장소에 넣을 수 없다. Vite 커스텀 플러그인을 만들어 개발 서버에서는 미들웨어로 서빙하고 빌드에서는 동일한 URL 구조로 복사한다. 덕분에 코드에 환경 분기가 남지 않는다.

Stack

기술 스택

외부 런타임 의존성이 사실상 없다. Express도, ws도, ORM도, 벡터DB도, LLM SDK도 쓰지 않는다. 서버는 Node 내장 http 하나이고 모든 외부 API 호출은 내장 fetch다. OBS WebSocket v5의 인증 핸드셰이크도 직접 구현했다.

Status

현재 상태와 한계

MVP 범위에서 동작한다. 규칙 응답, Live2D 표정·모션, 시선, 립싱크, 외부 LLM, 장기 기억, 음성 합성, OBS 송출까지 연결되어 있다. 다만 완성된 제품이 아니며 다음 한계가 있다.

  • 치지직 실연동이 없다. 방송 플랫폼 연동 코드는 존재하지 않으며 MVP 범위 밖이다. 채팅은 관리자 앱, 방송 화면 입력창, 별도 채팅 화면 3가지 경로로 넣는다.
  • 자동화 테스트가 없다. 테스트 파일과 CI 설정이 없고, 검증 기록은 전부 수동 검증이다.
  • 기억 검색에 시청자 필터가 없다. 저장은 시청자별로 되지만 검색은 전체를 대상으로 해서 다른 시청자의 기억이 섞일 수 있다.
  • 목소리가 캐릭터에 맞지 않는다. 현재 쓰는 음성은 모두 실제 사람 톤이라 애니풍 캐릭터 목소리가 아니다. 한국어 캐릭터 음성 확보가 남은 과제다.
  • Electron 방송 창을 지원하지 않는다. 방송 화면은 브라우저 전용이며 OBS Browser Source로 송출한다.
  • 장시간 송출 안정성이 검증되지 않았다. 30분 이상 연속 송출은 확인하지 않았다.

저장소를 clone해도 그대로 실행되지 않는다.

방송 화면이 렌더링하는 Live2D 모델은 구매한 상용 모델이고 렌더링 런타임은 Live2D Cubism SDK for Web이다. 둘 다 재배포가 금지되어 저장소에서 제외했다. 배치 방법은 README에 정리되어 있다.
