Overview

무엇을 만들고 있나

서버, 대시보드 화면, 스튜디오(Electron) 앱이 모두 127.0.0.1에서 동작하며 외부 호스팅을 쓰지 않는다. 데이터를 갱신하면 아래 순서로 대시보드와 보리의 대사가 만들어진다.

상위 랭커 경기 수집→ 조합별 집계→ 직전 갱신과 비교→ 사실 목록→ LLM 대사 · 숫자 검사→ 음성 합성→ 표정 · 립싱크
  • 조합 단위로 메타를 본다. 이번 시즌 랭크 경기만 골라 (캐릭터, 무기) 조합별 픽률·평균 순위·1등 비율·평균 MMR 증감을 낸다. 경기 수와 참가자 수를 따로 밝히고, 참가자 30명 미만 조합은 표본이 적다고 표시한다.
  • 지난번보다 무엇이 바뀌었는지 보인다. 갱신마다 기록을 남기고(최근 10개) 직전 갱신과 조합별로 비교한다. 시즌이나 패치가 바뀌었으면 함께 알린다.
  • 사실 문장은 서버가 만든다. 수치·캐릭터·무기 이름이 들어간 문장은 서버가 사실 목록에서 직접 만든다. LLM은 어떤 사실을 말할지와 수치·이름 없는 짧은 감상 한마디만 고른다. 감상에는 숫자·한글 수·이름·영문·효과/빌드/패치류 낱말을 금지하지만, 감상 내용의 정확성은 보장하지 않는다. LLM을 못 쓰거나 유효한 선택이 없으면 정해진 문장을 읽는다.
  • 내 전적도 같이 본다. 게임 닉네임을 한 번 저장하면 MMR·최근 10판·주캐릭터가 지금 메타에서 몇 위인지 보여 준다. 닉네임은 화면에만 보이고 로그와 LLM에는 넣지 않는다.
  • 목소리에 맞춰 입이 움직인다. 대사를 TTS로 합성하고, 음성 파형의 실효값을 읽어 입 벌림에 반영한다. 줄마다 감정에 맞는 표정을 낸다.

지금 상태(2026-11-21).

집계·비교·사실 목록·대사 검사·대시보드 화면을 서버 하나로 이었고, 가짜 이터널리턴·가짜 OpenAI 서버에 실제 서버를 붙여 "대시보드 열기 → 자동 갱신 → 대사 → 음성"까지 통합 검사로 확인했다. 실제 키로 끝까지 돌려 보는 확인과 Live2D가 뜬 실제 화면 확인은 아직 남았다. 이전에 만들던 치지직 방송 시스템과 1:1 대화 기능은 이번 방향 전환에서 지웠다.

Engineering

구현에서 신경 쓴 것

각 항목의 근거와 트레이드오프는 설계 문서에 정리했다.

서버가 조립하는 사실 문장

수치·캐릭터·무기 이름이 들어간 문장은 서버가 사실 목록에서 직접 만든다. LLM은 어떤 사실을 말할지와 수치·이름 없는 짧은 감상 한마디만 고른다. 감상에는 숫자·한글 수·이름·영문·효과/빌드/패치류 낱말을 금지하지만, 감상 내용의 정확성은 보장하지 않는다. LLM을 못 쓰거나 유효한 선택이 없으면 정해진 문장을 읽는다.

apps/server/src/narration/

호출 수를 늘리지 않는 집계

개인 키는 초당 1회라 갱신 한 번이 몇 분 걸린다. 원래 받던 경기 상세 응답에서 조합별 순위·MMR 증감·킬·딜량·코어 특성·부위별 장비를 함께 세서, 화면에 필요한 수치를 늘리면서도 API 호출은 그대로 두었다.

packages/er/src/meta.ts

프로바이더 무관 구조화 출력과 회로 차단기

JSON Schema 하나를 OpenAI는 Structured Outputs로, Anthropic은 강제 도구 호출로 감싼다. 클라이언트는 결과를 부르는 쪽의 parse 함수로 바꾸고, 호출 실패나 parse 거부가 이어지면 잠시 부르지 않는다. 속도 제한(429)은 고장으로 세지 않는다.

packages/llm/src/index.ts

SDK 내부 파이프라인에 개입한 립싱크

WebAudio로 계산한 파형 실효값을 입 벌림에 매핑하고 지수 평활로 떨림을 없앴다. 파라미터를 그냥 설정하면 Cubism SDK가 매 프레임 덮어쓰기 때문에, SDK 업데이트 순서를 분석해 정확한 지점에 주입해야 했다.

apps/companion/src/live2d/

로컬 API 보안 경계와 안전한 파일 저장

모든 요청이 라우트 앞에서 Host·Origin·Content-Type·본문 크기 검사를 거친다. 설정·사용량·집계 파일은 임시 파일에 쓴 뒤 rename으로 바꾸고, 깨진 파일은 원본을 남긴 채 기본값으로 시작한다. 화면에서 넣은 API 키는 암호화해 저장한다.

apps/server/src/http/ · atomic-file.ts

라이선스 제약을 빌드 파이프라인으로 해결

구매한 상용 Live2D 모델과 Cubism SDK는 재배포가 금지되어 저장소에 넣을 수 없다. Vite 플러그인으로 개발 서버에서는 미들웨어로 서빙하고 빌드에서는 같은 URL 구조로 복사한다. 코드에 환경 분기가 남지 않는다.

tools/vite/private-assets.ts

Stack

기술 스택

외부 런타임 의존성이 사실상 없다. Express도, ORM도, LLM SDK도 쓰지 않는다. 서버는 Node 내장 http 하나이고 모든 외부 API 호출은 내장 fetch다.

README

프로젝트 소개, 지금 되는 것과 아직 확인하지 않은 것, 실행 전 알아둘 제약, 설치와 실행 절차.

Status

현재 상태와 한계

  • 실제 키와 실제 화면으로 끝까지 확인하지 않았다. 집계·비교·대사 검사와 서버 연결은 고정 자료와 가짜 API(통합 검사)로 확인했다. Live2D가 뜬 대시보드는 아직 실제로 띄워 보지 않았다.
  • 표본은 상위 랭커 경기다. 기본 랭커 100명 × 최근 3판이라 전체 이용자 메타와 다를 수 있다.
  • 사용자 인증이 없다. 로컬 단일 사용자를 가정한다. 서버는 127.0.0.1에만 열리며 외부 공개 서버로는 쓸 수 없다.

저장소를 clone해도 그대로 실행되지 않는다.

보리를 그리는 Live2D 모델은 구매한 상용 모델이고 렌더링 런타임은 Live2D Cubism SDK for Web이다. 둘 다 재배포가 금지되어 저장소에서 제외했다. 배치 방법은 README에 정리되어 있다.
