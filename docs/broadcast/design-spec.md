# 보리 치지직 방송 시스템 설계

상태: 확정(2026-10-15, 사용자 승인) · 기준 브랜치: `fix/audit-followup`

## 1. 목표

보리를 실제 버추얼 스트리머처럼 OBS로 치지직에 송출하고, 3~5분짜리 시청자 참여형 방송을 시연한다.

제출 결과물은 다음 네 가지다.

1. 치지직 실제 라이브와 그 녹화본
2. 3~5분 시연 영상(OBS 녹화)
3. 기획서
4. 큐시트

과제가 요구하는 것은 기능 개수가 아니라 기획, 구성, 연출, 운영을 보여 주는 것이다. 그래서 이 설계는 그 네 가지를 보여 주는 데 필요한 만큼만 만든다.

## 2. 확정된 결정

| 항목 | 결정 |
|---|---|
| 콘텐츠 | 이터널리턴 메타 브리핑 + 질문 코너 + 전적 진단 (보리가 실제 게임 데이터로 답하는 AI 버튜버 콘텐츠) |
| 채팅 입력 | 보리 스튜디오 운영 탭의 "시청자 채팅"(닉네임 칸으로 여러 시청자를 흉내 낸다). 치지직에는 OBS 화면만 송출해 리허설 방송으로 녹화한다(2026-10-15 사용자 결정). 치지직 Open API 채팅 수신은 구현돼 있지만 시연에는 쓰지 않는다 |
| 채팅 치는 사람 | 진행자 본인(다른 계정 또는 휴대폰) |
| 전적 진단 대상 | 채팅에 `!전적 닉네임`을 친 사람이 알려 준 닉네임. 화면에는 닉네임 일부를 가려 표시, 보리는 닉네임을 읽지 않음, 조회 결과는 저장하지 않음 |
| 메인 장면 배치 | C안: 보리 왼쪽, 오른쪽 큰 대시보드, 채팅은 아래 띠 |
| 앱 형태 | 방송 화면은 OBS 브라우저 소스. 운영·1:1·설정은 Electron 앱 "보리 스튜디오" 하나로 통합 |
| OBS 구성 | 레이어를 나눈 브라우저 소스 + OBS 장면 4개 + 서버가 OBS WebSocket으로 장면 자동 전환 |
| 채팅 오버레이 | 치지직 위젯 대신 보리 서버가 받은 채팅을 C안 디자인으로 직접 그린다 |

## 3. 일반 버튜버 방송과의 관계

일반 버튜버는 다음 구조로 방송한다.

- 캐릭터: VTube Studio 같은 프로그램을 OBS로 가져온다(Spout2, 게임 캡처 투명).
- 채팅창·알림: 투네이션·위플랩 같은 위젯 URL을 브라우저 소스로 넣는다.
- 장면: 대기, 메인, 엔딩 등으로 나누고 전환 효과(스팅어)를 쓴다.

보리는 사람의 얼굴 인식이 아니라 AI가 표정과 모션을 정한다. 그래서 캐릭터를 웹 페이지(Live2D Cubism Web SDK)로 그리고, 그 페이지를 OBS 브라우저 소스로 넣는다. 다른 AI 버튜버 오픈소스(Open-LLM-VTuber)도 브라우저 렌더링을 쓴다.

나머지 구성(오버레이, 장면, 전환)은 일반 버튜버와 같다. 장면 자동 전환은 Streamer.bot 같은 도구 대신 보리 서버가 OBS WebSocket(v5, OBS 28+ 내장)으로 직접 한다.

## 4. 전체 구조

```
 [치지직 채팅] --(공식 Open API, Socket.IO)--+
                                            v
 [이터널리턴 API] --> [보리 서버 apps/server] <-- [보리 스튜디오 apps/studio (Electron)]
   (방송 전 집계 +          |   ^                  방송 운영 / 1:1 대화 / 설정
    !전적 실시간 조회)      |   +-- 장면 전환 (OBS WebSocket, 기본 포트 4455)
                            v
                 OBS용 페이지 (브라우저 소스, 1920x1080, 투명 배경)
                 /obs/character  보리 Live2D + TTS 음성
                 /obs/dashboard  시즌 정보 · TOP 5 · 캐릭터 카드 · 전적 카드 · 엔딩 요약
                 /obs/caption    보리 자막
                 /obs/chat       채팅 띠
                 /obs/waiting    대기 화면
                 /obs/ending     엔딩 화면
                            |
                            v
                 [OBS] 장면: 대기 / 메인 / 전적 진단 / 엔딩
                            |
                            v
                 [치지직 송출 + OBS 녹화]
```

### 4.1 구성 요소와 책임

| 구성 요소 | 하는 일 | 의존 |
|---|---|---|
| 방송 진행기 (`apps/server/src/show/`) | 진행 단계 상태와 단계 전환, 단계별 장면·대시보드·보리 첫 대사 결정 | 대화 엔진, OBS 제어, ER 데이터 |
| OBS 제어 (`apps/server/src/obs/`) | OBS WebSocket 연결, 장면 전환, 연결 상태 | `obs-websocket-js` |
| 치지직 채팅 (`apps/server/src/chzzk/`) | OAuth 인증, 토큰 갱신, 세션 연결, CHAT 이벤트를 기존 채팅 큐로 전달 | `socket.io-client@2.0.x` |
| ER 데이터 (`packages/er/`) | Open API 호출(초당 1회 제한 준수), 메타 집계, 캐릭터 사전, 전적 조회 | `fetch` |
| OBS 페이지 (`apps/overlay/`) | 위 6개 페이지. 서버 상태를 받아 그리기만 한다 | 서버 상태 API, `@bori/live2d` |
| 보리 스튜디오 (`apps/studio/`) | Electron 셸. 서버 자동 실행·종료, 방송 운영·1:1·설정 탭 | 기존 admin·companion 화면 재사용 |

기존 `apps/broadcast`(현재 방송 화면)는 OBS 페이지로 대체한다. 기존 `apps/admin`과 `apps/companion`의 화면은 보리 스튜디오의 탭으로 옮긴다.

옮긴 뒤 옛 앱을 지울지는 구현 계획에서 정한다. 이 문서에서 결정하지 않는다.

### 4.2 데이터 흐름 (질문 코너 한 건)

1. 치지직 채팅 "○○ 어때?"가 Socket.IO `CHAT` 이벤트로 들어온다.
2. 서버가 기존 채팅 파이프라인(차단 규칙, 위기 감지, 큐)에 넣는다.
3. 서버가 캐릭터 사전으로 채팅에서 캐릭터 이름을 찾는다.
4. 찾았으면 집계 데이터(픽률, 평균 순위, 주 무기, 표본 수)를 프롬프트의 `[게임 데이터]` 섹션에 붙여 LLM을 부른다. 지침은 "주어진 수치 안에서만 말하고, 없는 수치는 모른다고 말한다"이다.
5. 대시보드 상태를 해당 캐릭터 카드로 바꾸고, 보리 답(자막, 감정, 모션, TTS)을 내보낸다.
6. OBS 페이지가 상태를 받아 그린다.

## 5. 방송 진행 단계 (약 4분 30초)

| 단계 | OBS 장면 | 대시보드 | 보리 | 진행자 |
|---|---|---|---|---|
| ① 오프닝 0:00~0:30 | 대기 → 전환 → 메인 | 시즌 정보, 데이터 기준("최근 7일 상위 랭커 N판") | 인사, 오늘 할 것 소개 | "다음 단계" |
| ② 메타 브리핑 0:30~1:30 | 메인 | TOP 5가 한 칸씩 나타남 | 순위 소개, 1위에 놀라는 표정 | "다음 단계" |
| ③ 질문 코너 1:30~3:00 | 메인 | 질문받은 캐릭터 카드 | 데이터로 답함. 성적이 좋으면 신나고 나쁘면 아쉬워함 | 치지직 채팅 질문 2~3개 |
| ④ 전적 진단 3:00~4:00 | 전적 진단 | 전적 카드(닉네임 일부 가림, 최근 경기 순위, 주력 캐릭터) | 분석과 조언 한마디 | 채팅 `!전적 닉네임` |
| ⑤ 엔딩 4:00~4:30 | 메인 → 엔딩 | 오늘 나온 캐릭터 요약 | 정리 인사 | "다음 단계" |

- 각 단계에 들어가면 보리가 먼저 말한다. 첫 대사는 단계 지침과 데이터를 넣어 LLM이 만들고, 실패하면 단계별로 준비한 대사를 쓴다.
- 질문 코너에서 캐릭터 이름이 없는 채팅은 평소처럼 잡담으로 답한다.
- 단계와 관계없는 `!전적`은 전적 진단 단계에서만 받는다. 다른 단계에서는 "전적 진단 때 봐 드릴게요"라고 안내한다.
- 단계 전환은 진행자가 결정한다. 시간이 지나도 자동으로 넘어가지 않는다.

## 6. 이터널리턴 데이터

공식 Open API를 쓴다. 키는 루트 `.env`의 `ER_API_KEY`(개인 키, 초당 1회)에 있다. 2026-10-15에 실제로 확인했다: 현재 시즌 21(seasonID 41, 2026-11-12 종료), 상위 랭커 1,001명.

- **메타 집계(방송 전):** 스튜디오의 "데이터 갱신" 버튼으로 실행한다.
  - 상위 랭커 → 닉네임으로 uid 조회 → 최근 경기 목록 → 경기 상세 순서로 수집한다.
  - 캐릭터별 픽 수, 픽률, 평균 순위, 주 무기를 계산한다.
  - 초당 1회 제한으로 약 500호출, 10분 내외 걸린다.
  - 결과와 기준(기간, 표본 수, 수집 시각)을 `data/er-meta.json`에 저장한다.
  - 공식 API에는 픽률 엔드포인트가 없다. 화면과 보리 대사에는 "상위 랭커 표본 기준"이라는 한계를 밝힌다.
- **캐릭터 사전:** `/v1/l10n/Korean`과 `/v2/data/Character`, `CharacterMastery`로 한국어 이름, 코드, 무기를 만든다. 데이터 갱신 때 같이 받는다.
  - 채팅에서 이름을 찾을 때 띄어쓰기와 흔한 별칭을 허용한다. 별칭 목록은 구현 계획에서 정한다.
  - 못 찾으면 비슷한 이름을 제안한다.
- **전적 진단(방송 중):** 닉네임 → uid → 시즌 통계(`/v2/user/stats/uid/...`)와 최근 경기 순서로 호출한다.
  - 2~4초 걸리고, 그동안 보리가 "찾아볼게요!"로 시간을 채운다.
  - 결과는 메모리에만 두고 저장하지 않는다.
  - 화면의 닉네임은 앞 일부만 보인다(예: "보리팬**"). 보리는 닉네임을 말하지 않는다.
- **약관:** 다른 사람을 식별 가능하게 공개하는 것은 금지(이용 약관 금지 20호)라서 위 가림 규칙을 둔다. 수익 방송에서의 API 이용은 개발자 디스코드에 문의할 항목으로 남긴다(확인 필요).

## 7. 치지직 채팅 연동

공식 Open API(`https://openapi.chzzk.naver.com`)를 쓴다. 근거와 세부는 [chzzk-integration-review.md](../chzzk-integration-review.md)에 있다.

- 사용자가 개발자 센터에 앱을 등록하고 `CHZZK_CLIENT_ID`, `CHZZK_CLIENT_SECRET`을 `.env`에 넣는다.
- Redirect URL은 로컬 서버 콜백으로 한다. 정확한 경로는 구현 계획에서 정한다.
- 스튜디오의 "치지직 연결" 버튼을 누르면 기본 브라우저로 인증 페이지가 열린다. 승인하면 Access Token(1일)과 Refresh Token(30일, 1회용)을 받아 기존 `secret-store` 방식으로 암호화해 저장한다.
- 유저 세션(`GET /open/v1/sessions/auth`)을 만들고, Socket.IO로 연결한 뒤, 채팅을 구독한다. 공식 지원 클라이언트는 `socket.io-client` 1.0.0~2.0.3이다.
  - 이것은 새 런타임 의존성이다. 서버 패키지에만 두고 버전을 고정한다.
  - 해당 버전대의 보안 공지를 확인하고 결과를 기록한다.
- 끊기면 지수 백오프로 직접 재연결한다(라이브러리 자동 재연결은 끈다). 상태를 스튜디오에 표시한다.
- 개인정보: 닉네임과 채널 ID는 기존 방송 채팅 규칙대로 최소한으로만 다룬다. 시청자 기억 소유권은 1차 수정(F2)이 바꾼 규칙을 따른다.

## 8. OBS

- **페이지:** 모두 1920x1080, 배경은 투명이다. OBS 브라우저 소스는 기본 CSS가 투명 배경이다.
  - Live2D WebGL 캔버스의 알파 합성은 실제 OBS에서 확인해야 한다(미검증).
- **소리:** `/obs/character`만 소리를 낸다. 브라우저 소스의 "Control audio via OBS"를 켜서 OBS 믹서로 받는다. OBS 브라우저는 사용자 클릭 없이 자동재생을 허용한다. 현재 OBS 버전에서 실제로 되는지 확인한다.
- **장면:**

| 장면 | 소스 |
|---|---|
| 대기 | `/obs/waiting` |
| 메인 | `/obs/character` + `/obs/dashboard` + `/obs/caption` + `/obs/chat` |
| 전적 진단 | 메인과 같은 소스, 대시보드는 전적 카드 배치 |
| 엔딩 | `/obs/ending` |

- **전환:** 기본은 페이드 전환이다. 스팅어 영상은 선택 사항으로, 있으면 쓴다.
- **자동 전환:** 서버가 `obs-websocket-js`(v5)로 `SetCurrentProgramScene`을 호출한다. WebSocket 비밀번호는 `.env`의 `OBS_WEBSOCKET_PASSWORD`에 둔다.
  - OBS가 꺼져 있거나 연결이 끊기면 진행은 계속하고 스튜디오에 경고를 띄운다. 진행자는 OBS 단축키로 장면을 바꾼다.
- **송출:** OBS 서비스 목록의 CHZZK 서버, 1080p, 30 또는 60fps, 8000kbps CBR, 키프레임 1초, 하드웨어 인코더. 스트림 키는 사용자가 OBS에 직접 넣는다(저장소에 두지 않음).

## 9. 보리 스튜디오 (Electron)

- 실행하면 서버를 자식 프로세스로 띄우고, 앱을 끄면 서버도 끈다. 이미 떠 있는 서버가 있으면 그것을 쓴다.
- **방송 운영 탭:**
  - 현재 단계와 "다음 단계"·"이전 단계" 버튼
  - 연결 상태(치지직, OBS, LLM, 이터널리턴, TTS)
  - "데이터 갱신"(진행률, 마지막 갱신 시각)
  - 시청자 채팅 입력(시연의 기본 채팅 경로, 닉네임 칸)
  - OBS 페이지 주소 복사 버튼
  - 최근 채팅과 보리 답 로그
- **1:1 대화 탭:** 기존 `apps/companion` 화면
- **설정 탭:** 기존 `apps/admin`의 LLM·TTS·기억 관리 화면, 치지직 연결 버튼, OBS 연결 설정
- 보안: 1차 수정(F5)에서 정한 Electron 정책(`sandbox`, CSP, 외부 이동 차단, loopback만 로드)을 그대로 따른다.

## 10. 돌발 상황 대응

이 표는 큐시트에도 그대로 들어간다.

| 상황 | 자동 대응 | 진행자 대응 |
|---|---|---|
| 치지직 채팅 끊김 | 재연결, 스튜디오에 빨간 표시 | 스튜디오 테스트 채팅으로 대신 입력 |
| LLM 실패·지연 | 단계별 준비 대사 | 그대로 진행 |
| 없는 캐릭터·오타 | "못 찾았어요" + 비슷한 이름 제안 | - |
| `!전적` 닉네임 없음·API 실패 | "그 닉네임은 못 찾았어요" | 다른 닉네임으로 재시도 |
| ER 데이터 갱신 실패 | 마지막 저장 데이터 사용, 기준 시각 표시 | 방송 전에 미리 갱신 |
| OBS 연결 끊김 | 스튜디오 경고 | OBS 단축키로 장면 전환 |
| 부적절한 채팅 | 기존 차단 규칙과 위기 대응 | 필요하면 다음 단계 |
| 소리 안 나옴 | - | 체크리스트대로 OBS 오디오 확인 |

## 11. 제출 문서 (`docs/broadcast/`)

1. `plan.md` 기획서: 콘셉트, 주요 시청자, 참여 방식, 재미 요소
2. `structure.md` 구성안: 5단계 흐름과 단계별 목표
3. `direction.md` 연출: OBS 장면 4개의 소스 배치, 전환, 상황별 보리 표정, 화면 구성 그림
4. `cue-sheet.md` 큐시트: 시각, 길이, 순서, 장면, 대사 방향, 진행자 할 일, 돌발 상황 대응
5. `obs-setup.md` OBS 설정 안내서: 처음 한 번 하는 설정과 치지직 송출 설정
6. `rehearsal-checklist.md` 리허설 체크리스트

제출용 Word·PDF 변환은 마지막에 사용자가 원하면 한다. 시연 영상 녹화는 사용자가 직접 한다.

## 12. 검증

- **단위 테스트:**
  - 단계 전환 상태 머신
  - 캐릭터 이름 찾기(별칭, 오타)
  - 메타 집계 계산
  - 닉네임 가림
  - 치지직 이벤트 → 채팅 큐 변환
  - OBS 제어 실패 처리
- **통합 테스트:**
  - 가짜 치지직 소켓 서버, 가짜 ER API, 가짜 OBS WebSocket으로 5단계 전체를 자동으로 돌린다.
  - LLM은 기존 mock을 쓴다.
- **실제 확인:** 다음 항목은 사용자 환경에서 리허설로 확인하고, 확인하지 못한 것은 미검증으로 남긴다.
  - OBS 투명 합성
  - OBS 자동재생
  - 치지직 OAuth
  - 실제 ER 집계 시간
  - 실제 송출
- 기존 검사(typecheck, test:unit, test, eval)는 계속 통과해야 한다.

## 13. 작업 순서

| 순서 | 작업 | 선행 |
|---|---|---|
| 1 | OBS 페이지 6종(가짜 데이터로 먼저), C안 디자인, 투명 캐릭터 | 1차 수정 병합 |
| 2 | 방송 진행기와 OBS 자동 전환 | 1 |
| 3 | ER 데이터(집계, 사전, 전적) | 없음(1과 병렬) |
| 4 | 치지직 채팅 연동 | 없음(1과 병렬), 사용자의 앱 등록 |
| 5 | 보리 스튜디오 Electron | 2 |
| 6 | 제출 문서와 리허설 | 1~5 |

점검 후속 수정 2차 가운데 방송 운영 수정(F4)은 옛 방송 화면·관리자 화면 부분을 빼고 서버 공통 부분만 남긴다. 기억 정확도(F3)와 빌드·문서(F7)는 그대로 진행한다.

## 14. 사용자가 할 일

1. 치지직 개발자 센터(https://developers.chzzk.naver.com)에 앱을 등록한다.
   - 앱 이름에 "chzzk", "naver"는 쓸 수 없다.
   - Redirect URL은 구현 계획에서 정한 값을 넣는다.
   - `.env`에 `CHZZK_CLIENT_ID`, `CHZZK_CLIENT_SECRET`을 넣는다.
2. OBS를 설치하고 WebSocket 서버를 켠다. 비밀번호를 `.env`의 `OBS_WEBSOCKET_PASSWORD`에 넣는다.
3. 치지직 스트림 키를 OBS에 넣는다.
