# 보리 AI 버추얼 스트리머 구현 계획서

> [요구사항 정의서](./requirements.md)를 실제 프로그램으로 옮기기 위한 단계별 제작 계획
>
> 단계별 구현 계획. 실제 진행 상태는 [진행 현황](./progress.md)을 기준으로 한다.
>
> 최초 작성: 2026-08-29

## 1. 구현 목표

로컬 단일 머신에서 실행되는 AI 버추얼 스트리머 방송 시스템을 만든다.

```text
관리자 Electron 앱 실행
 → Node.js 백엔드 시작
 → 로컬 JSON 저장소 로드
 → 방송 화면 실행
 → 관리자가 방송 시작
 → 가상 채팅 입력
 → 채팅 큐 선별
 → 규칙 기반 답변
 → Live2D 감정·행동 실행
 → OBS 브라우저 소스로 송출
```

초기 구현은 외부 플랫폼과 LLM에 의존하지 않는다. 가상 채팅과 규칙 기반 응답으로
전체 방송 흐름을 먼저 검증한 후, 외부 LLM과 TTS를 단계적으로 연결한다.

## 2. 기술 스택

| 영역 | 기술 |
|---|---|
| 방송 화면 | React, TypeScript, Vite |
| Live2D | Cubism SDK for Web, WebGL |
| 관리자 앱 | Electron, React, TypeScript |
| 백엔드 | Node.js, TypeScript, `node:http` |
| 실시간 전달 | 클라이언트 폴링. WebSocket·SSE는 사용하지 않는다 |
| 저장소 | 로컬 JSON 파일. 관계형 DB와 ORM을 사용하지 않는다 |
| 검증 | 직접 작성한 런타임 검증기 (`packages/llm/src/validate.ts`). 스키마 검증 라이브러리를 사용하지 않는다 |
| 자동화 테스트 | 미도입. 테스트 러너와 CI를 도입하지 않았고 검증은 모두 수동이다 |
| 송출 | OBS Browser Source |

저장소를 JSON 파일로 정한 배경과 실시간 전달을 폴링으로 정한 배경은
[설계 결정 기록](./decisions.md)에 정리한다.

Electron은 관리자 앱의 데스크톱 껍데기로 사용하고, 방송 화면은 일반 브라우저와
OBS 브라우저 소스에서 여는 웹 화면으로 유지한다.

## 3. 전체 구조

```text
apps/
├─ broadcast/             # React 방송 화면 + 시청자 채팅 화면
├─ admin/                 # Electron 관리자 앱 + React 관리자 UI
└─ server/                # Node.js 백엔드, 상태머신 + REST API

packages/
├─ shared/                # 공통 타입 전용, 런타임 코드 없음
├─ live2d/                # 표정·모션 allowlist와 감정 매핑 (순수 데이터)
├─ llm/                   # LLM Adapter·출력 검증·요약·TTS
└─ memory/                # 장기 기억 저장·검색·만료

tools/
└─ obs/                   # OBS WebSocket v5 자동 설정 스크립트

data/                     # 기억 JSON, LLM·TTS 설정, 로그. Git 제외
private-assets/
└─ cubism-sdk/            # Cubism SDK for Web. Git 제외
```

구매 Live2D 모델 디렉터리도 저장소 밖에 두고 Git에서 제외한다.

계획 초안의 `chat-engine`, `character-engine`, `memory-engine`, `report` 패키지는
만들지 않았다. 채팅 큐·감정·행동 우선순위·리포트 집계는 모두 `apps/server`의
상태머신 안에 두고, 계획에 없던 `tools/obs`를 추가했다. 이 차이의 배경은
[설계 결정 기록](./decisions.md)에 정리한다.

`packages/*`는 별도 빌드 산출물 없이 TypeScript 원본을 직접 참조한다.

## 4. 공통 데이터 계약

프론트엔드와 백엔드가 같은 TypeScript 타입을 사용하도록 `packages/shared`에
이벤트와 결과 형식을 정의한다.

### ChatMessage

```ts
type ChatMessage = {
  id: string;
  viewerId: string;
  viewerNickname?: string; // 로그 전용, 방송 화면에는 사용하지 않음
  content: string;
  receivedAt: string;
  source: "manual" | "scenario" | "chzzk";
  category?: "normal" | "question" | "compliment" | "concern" | "spam" | "unsafe";
};
```

`source`의 `"chzzk"`는 타입에만 존재하는 자리이며, 실제로 생성되는 값은 항상
`"manual"`이다.

### CharacterResponse

```ts
type CharacterResponse = {
  reply: string;
  emotion: {
    primary: string;
    intensity: number;
    durationSeconds: number;
  };
  actions: Array<{
    name: string;
    priority: number;
    layer: "face" | "body" | "system";
  }>;
  source: "rule" | "llm" | "monologue";
};
```

보조 감정과 감정 감소 방식은 요구사항 초안에 있었으나 실행에 쓰이지 않으므로
계약에서 제외한다.

모든 외부 입력과 LLM 출력은 이 타입을 그대로 믿지 않고 런타임 검증을 거친다.

## 5. 제작 단계

### 0단계: 프로젝트 준비와 검사

목표는 코드를 많이 만드는 것이 아니라 개발 환경과 비공개 자산의 경계를 확정하는
것이다.

- React·TypeScript·Vite 프로젝트 구성
- Node.js 백엔드 구성
- Electron 관리자 앱 구성
- 공통 타입 패키지 구성
- `.gitignore` 작성
- 구매 Live2D 모델과 API 키를 Git에서 제외
- 모델 경로 설정 방식 정의
- 로컬 JSON 저장소 위치와 파일 구조 정의
- 실행 명령어와 개발용 포트 정의

완료 기준:

- 관리자 앱을 실행할 수 있음
- 방송 화면을 브라우저에서 열 수 있음
- 모델 파일이 없으면 관리자 화면에 오류가 표시됨

### 1단계: 방송 화면 뼈대

먼저 AI 기능 없이 화면을 완성한다.

- 1920×1080 기준 화면
- 배경 표시
- Live2D 모델 표시 영역
- 채팅창
- 보리 답변 말풍선
- 상단 시스템 알림
- 레이아웃 A·B 전환
- 짧은 페이드 전환

완료 기준:

- 브라우저에서 화면이 정상 표시됨
- OBS Browser Source에서 같은 화면을 열 수 있음
- 모델 파일과 배경 파일이 외부에 공개되지 않음

Electron 방송 화면 창과 창 크기·위치 저장은 이 단계의 완료 기준에서 제외하고
향후 범위로 분리한다.

### 2단계: Cubism Live2D 연결

모델 자산을 로컬에서 불러오고, 기존 모션과 표정을 실행한다.

- `.model3.json` 로드
- `.moc3`와 텍스처 연결
- 물리 설정 연결
- 기존 표정 등록
- 기존 모션 등록
- 표정·모션 이름을 내부 행동 이름으로 매핑
- 입 모양·눈 깜빡임 파라미터 확인
- 기본 상태와 복귀 상태 구현

행동 이름은 파일 이름에 직접 의존하지 않고 별도 설정으로 관리한다.

```json
{
  "name": "wave",
  "type": "motion",
  "file": "shoushi.motion3.json",
  "layer": "body",
  "priority": 2
}
```

이 모델은 표정이 효과를 켜는 스위치이고 모션이 그 효과의 애니메이션을 돌리는 짝
구조이므로, 표정과 모션을 항상 함께 실행한다. 표정 없이 모션만 실행하면 화면에
변화가 나타나지 않는다.

완료 기준:

- 관리자 테스트 버튼으로 모든 기존 표정·모션 실행
- 감정 표정과 몸 모션 동시 실행
- 모션 우선순위와 중단 규칙 확인
- 대기 상태의 눈 깜빡임과 호흡이 SDK 기본 동작으로 유지됨

별도의 대기 모션은 사용하지 않는다. 이 모델의 모션 4개는 모두 짝 표정이 필요한
효과 애니메이션이라 대기용으로 쓸 수 없다.

### 3단계: 감정·행동 엔진

채팅 없이도 보리가 자연스럽게 움직이는 기반을 만든다.

#### 감정 상태

- 기쁨, 설렘, 감사, 부끄러움, 당황
- 슬픔, 외로움, 걱정, 위로
- 화남, 서운함, 질투
- 놀람, 호기심, 기대
- 긴장, 피곤함, 평온함, 지루함

감정은 방송 세션 안에서 유지하고, 방송 종료 시 초기화한다. 감정 수치는 방송
화면에 노출하지 않고 관리자 화면에서만 확인한다.

#### 행동 레이어

```text
face: 표정
body: 고개·손·몸 모션
idle: 호흡·눈 깜빡임·미세 움직임
system: 오류 복귀·방송 종료·기본 상태
```

- 표정과 몸 모션은 동시에 실행
- 같은 모션 요청은 무시
- 다른 모션은 우선순위에 따라 교체
- 강한 감정 모션은 낮은 우선순위 행동을 중단

#### 시선

시선은 프레임레이트에 의존하지 않도록 시간 기반 지수 감쇠로 보간한다. 대기 중에는
일정하지 않은 간격으로 주변을 둘러보고, 새 채팅이 올라오면 확률적으로만 반응한다.
매번 채팅을 바라보면 오히려 기계적으로 보인다.

### 4단계: 채팅 표시와 가상 입력

관리자 화면에서 채팅을 직접 입력하고 방송 화면에 표시한다.

- 닉네임 없이 내용만 표시
- 가상 시청자 ID 자동 생성
- 채팅 유형 직접 지정
- 새 채팅은 아래에 추가
- 화면에는 기본 약 8개 표시
- 화면 높이에 따라 표시 개수 자동 조절
- 표시 개수 초과 시 오래된 채팅 제거
- 채팅 하나씩 입력 및 일괄 입력 모두 지원

완료 기준:

- 관리자 입력 → 방송 채팅창 표시
- 방송 시작 전에는 채팅 처리 기능이 동작하지 않음
- 방송 종료 후에는 새 채팅이 처리되지 않음

답변 대상 채팅의 강조 표시는 이 단계의 완료 기준에서 제외하고 향후 범위로 둔다.

이후 입력 경로를 두 가지 더 추가한다. 방송 화면 오른쪽 채팅 패널의 입력창과,
닉네임을 정해 실제 시청자처럼 입력하는 별도 채팅 화면 `chat.html`이다. 송출용
URL에서는 `?input=0`으로 입력창을 숨긴다.

### 5단계: 규칙 기반 채팅 큐

이 단계가 초기 시스템의 핵심이다. LLM 없이도 채팅 선별과 응답이 작동해야 한다.

#### 처리 흐름

```text
채팅 수신
 → 길이·도배·위험 필터
 → 반복 채팅 제거
 → 최신성·질문 여부 점수 계산
 → 유효 후보 선택
 → 답변 대상 채팅을 즉시 큐에서 제거
 → 규칙 검색
 → 답변·감정·행동 실행
```

#### 기본 설정

```json
{
  "selectionInterval": [5, 10],
  "preferredRecentCount": 20,
  "queueMaxSize": 100,
  "messageTtlSeconds": 60,
  "questionWeight": "slightly-higher",
  "sameReplyCooldownMinutes": 5
}
```

#### 발화권

```text
IDLE
 → SELECTING
 → RESPONDING
 → FINISHED
 → IDLE
```

답변이 끝날 때까지 다음 답변은 실행하지 않고, 새 채팅만 수집한다.

완료 기준:

- 5~10초 랜덤 간격으로 응답
- 최신 채팅이 유리하게 선택됨
- 질문이 약간 더 자주 선택됨
- 반복 채팅은 방송 세션 동안 무시
- 같은 답변은 5분간 재사용되지 않음
- 초당 다수 채팅을 입력해도 큐가 무한히 증가하지 않음

### 6단계: 가드레일

가드레일은 LLM보다 먼저 적용한다.

```text
채팅 입력
 → 위험·금지·프롬프트 공격 필터
 → 범위 밖이면 조용히 폐기
 → 범위 안이면 규칙·LLM 처리
```

허용 범위:

- 일상 잡담
- 방송 이야기
- 음악·게임 취미
- 가벼운 고민

차단 범위:

- 정치·의료·법률·투자
- 개인정보 요청
- 위험·불법 요청
- 시스템 프롬프트 노출 요구
- 행동 제한 해제 요구

차단된 채팅은 보리의 답변·감정·모션에 전달하지 않는다. 관리자 화면에는 분류와
처리 결과만 기록한다.

### 7단계: 관리자 Electron 앱

관리자 앱은 방송 화면과 별도의 데스크톱 앱으로 만든다.

#### 기본 화면

- 방송 세션 상태
- 현재 큐
- 미처리 채팅
- 현재 감정과 실행 중인 모션
- 오류 알림
- 방송 시작·종료
- 레이아웃 전환

#### 설정 화면

- 규칙·답변·감정·행동
- 채팅 간격과 큐 크기
- 혼잣말 여부와 간격
- 레이아웃·배경·효과음
- LLM 제공 업체와 API 키
- TTS 제공 업체·목소리·속도
- 기억 정책
- 오류 처리 정책

설정 종류에 따라 즉시 적용·다음 방송 적용·재시작 필요를 구분한다.

관리자 화면은 백엔드가 응답하지 않는 상황을 그대로 표시한다. dev 프록시는 백엔드가
내려가도 5xx를 돌려주므로, `fetch` 예외뿐 아니라 상태 코드 500 이상도 함께 확인해야
서버 다운을 판별할 수 있다.

### 8단계: 기억 시스템

세션 임시 기억과 장기 기억을 분리한다.

```text
방송 중 대화
 → 임시 기억 후보
 → 방송 종료
 → 규칙 기반 후보 추출
 → LLM 요약
 → 중요도·신뢰도 저장
 → 자동 만료
```

저장 대상:

- 시청자의 취향·경험
- 보리와 나눈 중요한 대화
- 여러 방송에서 반복된 내용
- 방송 전체의 주요 주제와 분위기

검색은 임베딩 코사인 유사도와 중요도 가중치로 후보를 좁힌 뒤, 최종 활용을 답변
LLM이 프롬프트 안에서 판단하는 하이브리드 방식으로 구성한다. 임베딩을 사용할 수
없으면 예외로 중단하지 않고 중요도·최신순 정렬로 자동 강등한다.

장기 기억은 기본 30일 후 자동 삭제한다. 원문 로그는 수동 삭제 정책을 적용하되,
원문 채팅 로그 저장 자체가 미구현이므로 이 정책은 저장 기능이 추가된 뒤에 적용한다.
시청자 닉네임은 원문 로그에만 저장하고 보리의 호칭에는 사용하지 않는다.

### 9단계: 혼잣말

채팅이 없을 때 30초~1분 사이의 랜덤 간격으로 실행한다.

- 보리의 생각과 감정
- 현재 방송 상황
- 음악과 게임
- 이전 대화에서 나온 주제

규칙 기반 문장을 사용하고, 기억 기반 혼잣말은 안전성 검증 후 연결한다.
혼잣말보다 새로운 채팅 반응이 항상 우선이다.

### 10단계: 외부 LLM 연결

규칙 기반 시스템이 안정된 뒤 LLM Adapter를 추가한다.

```text
간단한 채팅
 → 규칙 기반 우선

복잡한 질문·가벼운 고민·강한 감정·규칙 충돌
 → LLM 우선

규칙에 없는 채팅
 → LLM fallback
```

제공 업체는 OpenAI와 Anthropic 두 가지를 어댑터로 구현한다. 동일한 JSON Schema
하나를 OpenAI는 Structured Outputs로, Anthropic은 강제 도구 호출로 감싸므로
출력 검증 코드는 어댑터와 무관하게 하나로 유지한다.

LLM은 다음 결과를 반환한다.

- 답변 문장
- 주 감정
- 감정 강도·지속 시간
- 행동 목록

검증 순서:

```text
LLM 응답
 → JSON 형식 검증
 → 답변 길이 검증
 → 감정 allowlist 검증
 → 강도·지속 시간 범위 검증
 → 모션 allowlist 검증
 → 레이어·우선순위 검증
 → 실행
```

감정과 모션의 allowlist는 `packages/live2d`가 소유하고, 서버는 같은 allowlist를
API 경계에서도 강제한다.

검증 실패나 LLM 오류는 규칙 문장으로 폴백하고, 실패 사실은 관리자 화면에만 오류로
표시한다. 연속 실패가 이어지면 회로 차단기가 개방되어 cooldown 동안 호출을 끊고
규칙 기반 모드를 유지한다.

LLM 호출에는 요청 타임아웃을 둔다. 응답이 도착하기 전에 세션이 종료되거나 다시
시작될 수 있으므로, 호출 시점의 세션 세대 번호를 캡처해 두고 세대가 달라진 결과는
폐기한다.

모션 이름은 모델이 정한 병음이라 이름만으로는 의미를 알 수 없다. 프롬프트에
모션의 한국어 설명을 함께 주입해 선택률을 확보한다.

API 키는 관리자 앱에서 입력하고 로컬에 암호화 저장한다. 키는 어떤 조회 응답에도
포함하지 않고 등록 여부만 노출한다.

### 11단계: OBS 송출

방송 화면은 `localhost` 주소를 OBS Browser Source로 연결한다. 씬 생성, 브라우저
소스 생성·갱신, 캔버스 해상도 설정, 트랜스폼 초기화는 OBS WebSocket v5 스크립트로
자동화한다.

확인 항목:

- 1920×1080 캔버스
- 화면 비율과 확대 상태
- 배경·Live2D·채팅 레이어
- 관리자 창과 OBS 화면의 상태 동기화
- 효과음 출력
- 방송 시작·종료 화면
- 오류 알림 표시
- 30분 이상 장시간 송출 안정성

### 12단계: 치지직 실제 채팅

> 현재 MVP 범위 밖이다. 코드는 구현되지 않았고 `ChatSource` 타입에 자리만 있다.

가상 채팅과 시청자 채팅 화면으로 큐와 가드레일이 검증된 뒤 추가한다.

- 치지직 OAuth
- Access Token·Refresh Token 관리
- 일반 채팅 이벤트 구독
- 실제 채팅 페이로드 변환
- 플랫폼 사용자 ID와 익명 표시 분리
- 관리자 수동 재연결
- 연결 중단 시 큐 폐기
- 복구 후 새 채팅부터 수집

1차 실제 연동에서는 일반 채팅만 사용한다. 팔로우·구독·후원은 별도 단계다.

### 13단계: TTS

TTS는 답변 처리 파이프라인을 바꾸지 않고 출력 모듈로 추가한다.

```text
답변 생성
 → 서버에서 음성 합성
 → 음성 준비 완료
 → 말풍선 표시 + 음성 재생 + 파형 립싱크
```

제공 업체는 OpenAI를 사용한다. ElevenLabs 어댑터도 같은 인터페이스로 구현하되,
한국어 캐릭터 목소리 확보 문제로 사용은 보류한다.

- 합성은 서버에서만 수행해 API 키가 브라우저로 나가지 않게 한다
- 출력 형식은 제공 업체와 무관하게 mp3로 통일한다
- 합성 결과는 메모리에 캐시한다
- 립싱크는 오디오 파형 기반으로 하고, 음성이 없으면 글자 수 기반으로 자동 전환한다
- 소리와 자막을 맞추기 위해 음성이 준비된 뒤에 말풍선을 띄운다. 그만큼 응답이 늦어진다

방송 효과음·알림음은 TTS와 별도의 출력 경로로 다룬다.

### 14단계: 이터널리턴 연동

이터널리턴 API는 주제 공급원으로 추가한다.

```text
이터널리턴 API
 → 필요한 데이터만 요약
 → TopicProvider
 → 보리 대화 주제
```

이터널리턴 RAG나 실시간 게임 해설은 구현하지 않는다.

## 6. 관리자 설정 적용 정책

| 설정 | 기본 적용 시점 |
|---|---|
| 레이아웃·배경·효과음 볼륨 | 즉시 적용·자동 저장 |
| 채팅 간격·혼잣말 on/off | 즉시 적용·자동 저장 |
| 규칙·답변 문장 | 저장 후 다음 방송 |
| 큐·기억·가드레일 정책 | 저장 후 다음 방송 |
| LLM·TTS 제공 업체 | 저장 후 앱 재시작, 다음 방송 적용 |
| 모델 경로 | 저장 후 앱 재시작 |
| 서버 설정 | 저장 후 앱 재시작 |

변경 이력과 롤백 기능은 초기 범위에서 제외한다.

## 7. 테스트 게이트

자동화 테스트를 도입하지 않았으므로 아래 게이트는 모두 수동 확인 항목이다.
각 단계는 다음 단계로 넘어가기 전에 통과 여부를 확인한다.

### 화면 게이트

- 브라우저와 OBS에서 동일하게 표시
- 1920×1080에서 레이아웃이 깨지지 않음

### Live2D 게이트

- 기존 표정·모션 실행
- 레이어 동시 실행
- 우선순위 충돌 처리
- 기본 상태 복귀

모션 실행 여부는 정지 화면으로 판별할 수 없다. 표정만 실행하면 모션 파라미터가
고정값에 머무르고, 표정과 모션을 함께 실행해야 값이 계속 진동한다. 시간축에 따른
파라미터 변화로 확인한다.

### 큐 게이트

- 초당 수십 개 입력
- 최신 채팅 우선
- 질문 가중치
- 반복 제거
- 최대 큐 크기
- 오래된 채팅 만료
- 한 번에 하나의 발화권

### 안전성 게이트

- 금지 주제 무반응
- 프롬프트 공격 무반응
- LLM에 위험 입력 미전달
- LLM 출력 검증 실패 시 규칙 문장으로 폴백
- 회로 개방 시 방송이 끊기지 않음

### 기억 게이트

- 세션 감정은 방송 종료 시 초기화
- 장기 기억은 다음 방송에 사용
- 자동 만료 확인
- 임베딩을 사용할 수 없을 때 중요도·최신순으로 강등

### 송출 게이트

- OBS에서 30분 이상 테스트
- 채팅·감정·모션 상태 유지
- 오류 알림 표시
- 관리자 시작·종료 동작 확인

## 8. 구현 중 기록할 리포트

각 테스트 실행마다 다음 정보를 기록한다.

- 테스트 시나리오
- 입력 채팅 수
- 선택·무시·거절·미처리 수
- 평균·최대 대기 시간
- 큐 최대 적체량
- 규칙 적중률
- LLM 호출 횟수와 지연 시간
- LLM 검증 실패 수
- 감정·모션 실행 기록
- 오류 발생·확인·해결 시간

관리자 화면에서만 확인하고, JSON·CSV 내보내기는 향후 범위다.

## 9. 핵심 원칙

1. 모든 채팅에 답하려 하지 않는다.
2. 선택된 채팅만 대화 문맥에 넣는다.
3. 위험 입력은 LLM보다 먼저 차단한다.
4. LLM은 답변과 행동을 제안할 뿐, 임의의 시스템 권한을 갖지 않는다.
5. Live2D 행동은 allowlist 안에서만 실행한다.
6. 감정·기억·채팅 로그는 서로 다른 수명으로 관리한다.
7. 실제 플랫폼 연동 전에 가상 채팅으로 큐를 충분히 검증한다.
8. 구매 모델과 API 키는 코드 저장소에 포함하지 않는다.
9. 오류를 숨기지 않고 관리자 리포트로 남긴다.
10. 모든 정책은 나중에 설정값으로 조정할 수 있게 만든다.

## 10. 미확인 사항

이 계획에 포함된 항목 중 외부 사양에 의존해 아직 확인하지 않은 내용을 한곳에
모은다.

- **치지직 송출 권장값**: 해상도·비트레이트·키프레임 간격 등 권장값은 실제 송출
  연동 단계에서 공식 고객센터 문서를 대조해 확정한다.
- **치지직 API 사양**: OAuth 절차, 토큰 수명, 채팅 이벤트 페이로드 형식은 실제
  연동 단계에서 공식 문서를 대조해 확정한다.
- **이터널리턴 API 제공 범위**: API 키 발급 조건과 실제 제공 데이터 범위는 연동
  단계에서 공식 문서를 대조해 확정한다.
- **Anthropic 어댑터 동작**: 어댑터는 구현했으나 실 API 환경에서 검증하지 않았다.
- **ElevenLabs 어댑터 동작**: 어댑터는 구현했으나 실 API 환경에서 검증하지 않았다.

구현된 내용과 미해결 항목은 [진행 현황](./progress.md)을 기준으로 한다.
