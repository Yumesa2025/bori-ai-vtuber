# 표본 확대와 WebGL 복구 계획

1. 기본 판수 정의 한 곳을 10으로 바꾸고 환경변수와 운영 안내(최대 약 22분)를 갱신한다.
2. 순수 ETA 함수와 WebGL 상태 전이·프레임 중단 검사를 먼저 작성해 실패를 확인한다. 경계 안 src에 검사를 두고 별도 명령으로 실행한다.
3. ER 갱신 시작 시각과 진행률로 서버 ETA를 계산하고 5% 미만·종료 상태는 null로 보낸다. 두 화면에 분 단위 안내를 붙인다.
4. SDK run의 프레임 예약을 래핑해 손실 시 중단한다. 캔버스를 숨기고 복구 안내, 10초 제한, 복구 시 인스턴스 재생성을 구현한다. 모델 로딩 중 취소와 언마운트도 정리한다.
5. 경기 상세 보관과 집계 파일 구조를 읽어 표본 확대 영향을 확인한다. 가능하면 가짜 SDK smoke를 추가한다.
6. 필수 검사 다섯 가지와 새 검사를 실행하고 작은 한국어 커밋으로 남긴다. push, main 대상 PR, CI watch까지 확인한다.

실제 키·비공개 자산은 복사하지 않는다. SDK 텍스트만 읽어 확인한다.

## 구현·검증 기록

- 기준 main 6015051에서 feature/sample-and-webgl 생성.
- 새 순수 검사 2개가 모듈 미구현으로 실패함을 확인한 뒤 구현, 프레임 예약 취소 검사까지 3개 통과.
- 기존 응답과 호환되도록 대기 상태에서는 선택 ETA 필드를 생략한다. 새 검사는 허용 경계인 src에 두고 dashboard-smoke 시작 시 함께 실행한다.
- 가짜 SDK smoke에 손실 시 preventDefault·캔버스 숨김·복구 시 단일 캔버스·10초 시간 초과를 추가했다.
- 단위 578/578, 통합 66/66, 하네스 8/8 통과. 타입 검사 8개 워크스페이스 통과, 브라우저 smoke 8/8 통과.
- 메모리·파일은 코드 구조로 확인했다: 경기마다 상세를 버리고 경기 ID와 조합 카운트만 누적, 저장 파일도 집계만 포함한다. 실제 API 10판 수집의 최대 메모리/파일 크기 및 실제 비공개 SDK 복구는 실행하지 않았다.
