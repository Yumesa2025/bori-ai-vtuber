# API 키 OS 보호 이전 계획

기준: main(6015051), feature/secret-store-dpapi. 설계 문서·README·ADR-028을 읽었다. superpowers 스킬은 제공되지 않아 직접 계획한다.

1. 회귀 검사를 먼저 추가하고 실패를 확인한다. 가짜 보호기를 주입해 v1 이전·원본 백업·재시작·손상/누락·보호 실패·오류 비밀값 비노출을 검사한다. Windows에서만 실제 DPAPI 왕복을 검사한다.
2. secret-store에 비동기 시작 초기화를 추가한다. 두 설정 파일을 먼저 확인하고 무작위 32바이트 마스터 키를 생성 또는 복호화한다. Windows CurrentUser DPAPI는 execFile/stdin/시간 상한으로 호출한다. 비Windows는 OS 보호 없이 0600 파일을 사용하며 임시 파일도 0600을 적용한다.
3. AES-GCM enc.v2를 기본으로 쓰고 v1 파생 재료는 그대로 유지한다. 초기화 시 읽을 수 있는 v1만 원본 백업 후 원자적으로 이전한다. v2가 있거나 파일을 읽지 못하면 키 재생성을 금지하고 안전한 오류로 알린다. 풀지 못한 값은 보존한다.
4. index.ts 키 로드 전에 초기화만 연결한다. 기존 슬롯 검사와 데이터 안전성 검사는 승인된 범위에서 초기화·v2 기대값만 변경한다.
5. 보안·운영 문서에 백업, 같은 Windows 계정 복구, 다른 PC에서 키 재입력, Linux 보호 한계를 기록한다.
6. typecheck, test:unit, test, test:harness, test:dashboard-smoke를 실행한다. 작은 한국어 커밋으로 push하고 한국어 PR을 작성한 뒤 CI를 포그라운드에서 확인한다.

실제 원래 체크아웃의 data/ 및 키는 읽지 않는다. 실제 데이터 이전 검증은 병합 후 코디네이터가 맡는다.

## 실행 결과

- 먼저 새 검사 실행: initializeSecretStore 미구현으로 1건 실패 확인(0 통과).
- 구현 후 Windows: typecheck 8개 워크스페이스 통과, 단위 검사 587 통과·0 실패·1 건너뜀(비Windows 0600), 실제 DPAPI 왕복 포함.
- 하네스 8/8, Chromium 대시보드 smoke 5/5 통과. 통합 검사는 PR 본문에 최종 실행 수를 기록한다.
- 계획 변경: 코디네이터 승인으로 api-key-slot.test.ts와 data-safety.test.ts에 임시 폴더·가짜 보호기 초기화/정리를 추가했다. 슬롯 검사의 출력 접두사 2곳만 v2로 바꾸고 기존 검사 성질은 유지했다.
- 원래 data/는 열지 않았다. 실제 사용자 데이터 이전은 코디네이터가 병합 후 백업을 만든 뒤 확인한다.
