# 과제 A 세부 계획: 보리 감상 한마디 다양화

브랜치 `feature/comment-variety` (main 6015051에서).
경계: `apps/server/src/narration/**`, `apps/server/test/narration-*`, (생성 설정이 필요할 때만) `apps/server/src/narration-llm.ts`, (필요하면) `tools/test/mock-openai.mjs`.

## 목표

#63(Z1) 뒤 감상이 남는 비율은 90% 이상이 됐지만, gpt-4o-mini가 지시문의 예시를 그대로 베껴 말이 단조롭다(고정 사실 50줄 중 48줄이 예시 복사).
안전장치(comment.ts 규칙, 수치·이름은 서버 문장만)는 그대로 두고 감상을 다양하게 만든다.

목표 지표(실제 사실·고정 사실 각각 10회 이상, gpt-4o-mini, 서버 기본 설정):
- 감상이 남는 줄 비율 ≥ 70%
- 남은 감상 중 서로 다른 문장 비율 ≥ 70%
- 예시 복사 비율(LLM 원래 감상 중 예시와 같은 것) — 줄어드는지 본다. 복사는 이제 버리므로 남은 감상에는 0이어야 한다.

## 1. 예시 묶음과 무작위 고르기 — 새 파일 `narration/examples.ts`

- `COMMENT_EXAMPLE_POOL`: 사실 종류(kind)마다 감상 예시 10개 안팎. 기존 21개를 포함한다.
- `pickCommentExamples(random, perKind = 2)`: 종류마다 `perKind`개를 무작위로 고른다(부분 Fisher–Yates). `random`은 `() => number`(0 이상 1 미만).
- `seededRandom(seed)`: 검사·측정용 시드 난수(mulberry32).
- 검사(`narration-examples.test.ts` 새 파일):
  - 묶음의 모든 예시는 `checkComment`를 통과한다(고정 이름 사전).
  - 모든 종류에 `perKind`보다 많은 예시가 있다. 묶음 안에 같은 문장(정규화 기준)이 없다.
  - 같은 시드면 같은 결과, 다른 시드면 대체로 다른 결과. 고른 예시는 모두 그 종류 묶음 안에 있고 겹치지 않는다.

## 2. 지시에 고른 예시만 싣기 — `writer.ts`

- `narrationSystemPrompt(examples)`: 고른 예시를 받는다. `GOOD_COMMENT_EXAMPLES` 상수는 묶음(examples.ts)으로 옮긴다.
- 지시에 "예시 문장을 그대로 쓰면 서버가 버린다"를 더한다.
- `writeLines(llm, facts, { timeoutMs, random? })`: 부를 때마다 `random`(기본 `Math.random`)으로 예시를 고른다.
- `NarratorDeps.random?`: narrator가 writeLines에 넘긴다(검사에서 시드 고정).
- 검사(narration-writer): 같은 시드면 같은 지시, 지시에 든 좋은 예시는 고른 것뿐이고 고르지 않은 예시는 없다.

## 3. 베낀 감상·되풀이 감상 버리기 — `check.ts`

- `commentKey(text)`: NFC, 공백·문장부호(`.,!?~…` 등 글자·숫자가 아닌 것)를 지운 글. examples.ts에 둔다.
- 감상이 안전 규칙(checkComment)을 통과한 뒤:
  - 키가 묶음의 어떤 예시와 같으면 `copied`로 버린다(지시에 실린 것만이 아니라 묶음 전체).
  - 키가 같은 대사에서 이미 붙인 감상과 같으면 `repeated`로 버린다(두 번째부터).
- 버린 이유 타입: `CommentDropReason = CommentReason | "copied" | "repeated"`. narrator 로그 요약(`검사에서 감상 N개를 버렸습니다 (…)`)에 그대로 나온다.
- 검사 먼저(narration-check, narration-narrator): 예시 그대로·공백/문장부호만 다른 것은 copied, 낱말이 다르면 남음, 같은 감상 두 번째는 repeated, 로그에 copied·repeated.
- mock-openai: 지금은 2~4번 줄에 같은 감상("좋아 보여요.")을 붙여 두 번째부터 repeated로 버려진다. 줄마다 다른 감상(모두 " 좋아 보여요."로 끝남: dashboard.mjs 검사와 맞춤)으로 바꾼다.

## 4. 생성 설정

- `LlmRequest`(packages/llm, 경계 밖)에 temperature 칸이 없다. OpenAI 기본 온도는 1이다.
- 먼저 1~3만으로 측정하고, 서로 다른 감상 비율이 목표에 못 미칠 때만 코디네이터에게 묻는다.

## 5. 측정

- 측정 스크립트는 저장소에 넣지 않는다(세션 스크래치, 키 사용).
- 키는 원래 체크아웃 `.env`의 `OPENAI_API_KEY`만 명령 환경변수로 넘긴다(출력·기록 금지).
- 실제 사실: `C:\project\HroovProject\data\er-snapshot.json`만 OS 임시 폴더로 복사해 `createErData`로 읽고 `buildFacts`(사전 이름 검사 포함).
- 고정 사실: narration-fixtures.
- 각 10회 `writeLines` → `composeLines`. 수정 전은 main 코드(같은 스크립트, 워크트리 main 커밋)로 다시 잰다.

## 6. 확인

`npm run typecheck`, `npm run test:unit`, `npm test`, `npm run test:harness`, `npm run test:dashboard-smoke`.

## 실행 기록

### 계획과 다른 점

- **종류별 예시 문장을 지시에 싣지 않는다.** 계획(종류마다 2개를 무작위로 골라 싣기) 그대로 재니 gpt-4o-mini가 그 종류 줄에 예시를 그대로 옮겨 적어,
  베낀 감상을 버리자 남는 줄이 실제 38%, 고정 6%로 떨어졌다. "이미 쓴 말이다"(v1), 종류당 1개(v4), 말머리만(v6) 모두 효과가 없거나 나빴다.
  채택: 꼴 보기 문장 4개(서로 다른 종류에서 하나씩, 종류는 밝히지 않음) + 종류별 느낌 낱말 3개(`COMMENT_FEELING_POOL`)를 부를 때마다 무작위로 싣는다.
  `pickCommentExamples`는 `{ samples, feelings }`를 돌려준다. 묶음(`COMMENT_EXAMPLE_POOL`, 종류마다 10개)은 그대로 두고 베낌 판정은 묶음 전체로 한다.
- **예비 감상(backup)을 더했다.** 예시를 덜 베끼게 하자 LLM이 자기 말로 쓴 감상이 이름·지표·'조합'·'캐릭터'로 자주 버려져, 프롬프트만으로는
  회차마다 57~85%로 흔들렸다(v7~v10). 스키마에 `backup`(필수, strict)을 더하고, comment가 비었거나 어떤 이유로든 버려지면 backup을 같은 검사(안전 규칙 → copied → repeated → length)로 본다.
  두 감상 모두 안전 규칙을 그대로 받는다. 버린 감상은 둘 다 이유를 센다. `backup`이 없는 응답(가짜 OpenAI 등)도 받는다. 출력 토큰은 줄마다 감상 하나만큼 는다(상한 1024는 그대로).
- **지시 문구:** "15자 안팎, 서너 어절", "[사실 목록] 문장의 낱말(이름·'픽률'·'순위'·'참가자'·'조합'·'캐릭터')은 하나도 쓰지 않는다", 끝맺음을 여러 가지로.
  규칙 줄의 예문 '꽤 안정적으로 보여요.'도 그대로 베껴 지웠다.
- **종류 이름:** main의 `[종류: 내 주캐릭터]`가 감상의 '주캐릭터'(금지 낱말)를 불러 `내가 자주 하는 것`으로 바꿨다.
- **예시·느낌 낱말 고치기:** 실제 사전(er-snapshot, 이름 1336개)으로 재니 예시 5개가 이름에 걸렸다('물', '바람'→바람 채찍, '반가운'→백색 가운, '정도면'→정교한 도면).
  바꿨다. 느낌 낱말 '위로'는 '위'(단위)+'로'로 걸려 '다독임'으로 바꿨다(검사로 고정). 사전 검사는 측정 스크립트에서만 했다(실제 사전은 저장소에 없다).
- **생성 설정(온도):** `LlmRequest`(packages/llm, 경계 밖)에 온도 칸이 없어 바꾸지 않았다. 위 두 가지로 목표를 넘었다.
- **검사 고침:** narration-regression의 무해한 감상 예문 중 묶음에 든 문장("요즘 정말 자주 보여요." 등)은 이제 copied로 버려져, 같은 규칙을 보는 묶음 밖 문장으로 바꿨다.
  가짜 OpenAI는 2~4번 줄에 같은 감상을 붙여 repeated에 걸려, 줄마다 다르되 모두 "좋아 보여요."로 끝나게 바꿨다(dashboard.mjs 검사는 그대로).

### 측정(gpt-4o-mini, 서버 기본 설정)

같은 스크립트(세션 스크래치, 저장소 밖). '감상 남음'은 서버 문장 뒤에 감상이 붙은 줄, '서로 다른'은 남은 감상 중 공백·문장부호를 뺀 글이 서로 다른 수,
'예시 복사'는 LLM이 쓴 comment(빈 것 제외) 중 예시 묶음 문장과 같은 수(수정 전은 그때의 예시 21개 기준).

| 단계 | 묶음 | 회 | 감상 남음 | 서로 다른 | 예시 복사 | 버린 이유 |
|---|---|---|---|---|---|---|
| 수정 전(main) | 실제 | 10 | 37/40 (93%) | 18/37 (49%) | 23/40 (57%) | metric 1, word 1, name 1 |
| 수정 전(main) | 고정 | 10 | 49/50 (98%) | 16/49 (33%) | 46/51 (90%) | metric 1 |
| 계획대로(종류별 예시 2개 + copied) | 실제 | 10 | 15/40 (38%) | 15/15 | 18/39 (46%) | copied 16, word 4, name 3, metric 1 |
| 계획대로 | 고정 | 10 | 3/50 (6%) | 3/3 | 45/50 (90%) | copied 45, name 2 |
| v8(종류별 예시 + 느낌) | 실제 | 10 | 33/40 (83%) | 31/33 (94%) | 2/40 (5%) | word 3, copied 2, … |
| v8 | 고정 | 10 | 24/50 (48%) | 24/24 | 18/50 (36%) | copied 18, word 6, … |
| v10(꼴 보기 + 느낌, backup 없음) | 실제 | 10 | 23/40 (57%) | 22/23 (96%) | 1/36 (3%) | word 6, metric 3, … |
| v10 | 고정 | 10 | 35/50 (70%) | 35/35 | 5/52 (10%) | word 6, copied 5, … |
| **채택(+ backup)** 1차 | 실제 | 10 | 35/40 (88%) | 34/35 (97%) | 0/40 | backup으로 살린 줄 16 |
| **채택** 1차 | 고정 | 10 | 38/50 (76%) | 38/38 (100%) | 4/50 (8%) | backup으로 살린 줄 24 |
| **채택** 2차 | 실제 | 10 | 35/40 (88%) | 35/35 (100%) | 0/39 | backup 20 |
| **채택** 2차 | 고정 | 10 | 43/50 (86%) | 43/43 (100%) | 2/50 (4%) | backup 27 |
| **채택** 최종(커밋 3a0703e) | 실제 | 12 | **43/48 (90%)** | **43/43 (100%)** | **1/45 (2%)** | number 8, word 8, metric 5, name 3, copied 2 / backup 19 |
| **채택** 최종 | 고정 | 12 | **53/60 (88%)** | **52/53 (98%)** | **2/62 (3%)** | word 17, metric 12, name 3, copied 3, sentence 1 / backup 25 |

남은 감상에 예시 복사는 0이다(copied로 버린다). 같은 대사 안 되풀이(repeated)는 측정 중 나오지 않았다.

### 남은 문제

- 자기 말로 쓰게 하자 사실과 어긋나거나 엉뚱한 감상이 규칙을 통과한다: "시장 규모가 커요.", "존경받는 인물인 것 같아요.",
  "이전보다 조금 내려간 것 같아요."(사실을 낱말만 바꿔 되풀이), "상당히 좋은 변화지만 아쉽기도 해요." 수치·이름은 없어 안전에는 문제가 없지만 말맛은 예시 복사 때보다 고르지 않다.
- 첫 감상은 여전히 절반쯤 버려지고(이름·지표·'조합'), backup이 그 자리를 메운다. 모델을 바꾸거나 온도 칸을 packages/llm에 더하면 다시 재 볼 만하다.
