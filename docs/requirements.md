# 보리 AI 버추얼 스트리머 요구사항 정의서

> 요구사항 확정본. 현재 구현 상태는 [진행 현황](./progress.md)을 기준으로 한다.
>
> 최초 작성: 2026-08-29

## 1. 프로젝트 목표

실제로 송출할 수 있는 AI 버추얼 스트리머 방송 화면을 제작한다.
보리라는 Live2D 캐릭터가 일반 채팅을 선별해 답변하고, 답변의 감정과 상황에 따라
표정·모션·효과음을 실행한다.

이 프로젝트는 실제 방송에 사용할 수 있어야 하며, 동시에 각 모듈의 책임을 분리해
설계 의도를 외부에 설명할 수 있어야 한다. 설명 대상이 되는 기술 축은 다음과 같다.

- 실시간 채팅 선별 큐
- 규칙 기반 답변과 외부 LLM fallback
- 프롬프트 공격 및 범위 밖 질문 차단
- 세션 기반 감정 상태
- 방송 간 장기 기억
- Live2D 행동 제어
- 테스트 시나리오와 오류 리포트

## 2. 캐릭터 설정

| 항목 | 설정 |
|---|---|
| 이름 | 보리 |
| 정체성 | AI 버추얼 스트리머 |
| 성격 | 감정 표현이 풍부하고 귀여움 |
| 말투 | 한국어 존댓말 |
| 시청자 호칭 | 여러분 |
| 취미 | 음악과 게임 |
| 취향 | 처음에는 폭넓게 시작하고 대화를 통해 확립 |
| 방송 콘셉트 | 초기에는 소통 방송, 이후 이터널리턴 전문 방송 |

보리는 필요할 때 자신을 AI 버추얼 스트리머라고 소개하지만, 시스템 용어를
과도하게 사용하지 않는다. 시청자와의 대화는 자연스러운 캐릭터 말투를 우선한다.

## 3. 기술 방향

```text
관리자 Electron 앱
 ├─ 방송 세션 시작·종료
 ├─ 설정·기억·로그 관리
 ├─ 가상 채팅 입력
 └─ 오류·테스트 리포트

공통 Node.js 백엔드
 ├─ 채팅 큐
 ├─ 규칙 기반 답변
 ├─ 외부 LLM Adapter
 ├─ 기억·요약
 └─ Live2D·방송 화면과 통신

방송 화면
 ├─ React + TypeScript
 ├─ Live2D Cubism SDK for Web
 ├─ 브라우저 단독 실행
 └─ OBS 브라우저 소스

저장소
 └─ 로컬 JSON 파일
```

프로그램은 로컬 단일 머신에서만 실행한다. 관리자 앱 하나를 실행하면 백엔드와
방송 화면도 함께 시작하는 것을 기본값으로 한다.

저장소는 관계형 DB나 ORM을 도입하지 않고 로컬 JSON 파일을 사용한다. 이 결정의
배경은 [설계 결정 기록](./decisions.md)에 정리한다.

## 4. Live2D 자산

Live2D 모델은 상용 라이선스로 취득한 모델이므로 재배포가 금지되어 저장소에서
제외한다. 준비한 배경·효과음도 같은 이유로 저장소에서 제외하고 로컬 경로 설정으로
연결한다.

모델 구성:

- `.model3.json`, `.moc3`, 물리 설정 파일 존재
- 모션 4개: `xingxingyan`, `kuqi`, `shengqi`, `shoushi`
- 표정 8개: `xingxingyan`, `kuqi`, `shangxin`, `shengqi`, `shoushi`, `wuyu`, `chidai`, `changfa`
- 눈 깜빡임과 입 모양 제어 파라미터 존재

이 모델은 표정 파일이 효과를 켜는 스위치이고 모션 파일이 그 효과의 애니메이션을
돌리는 짝 구조다. 표정 없이 모션만 실행하면 화면에 변화가 나타나지 않는다.
따라서 감정 매핑은 표정과 모션을 한 쌍으로 다룬다.

추가 표정·모션은 Cubism Editor Pro에서 직접 제작한다. LLM은 등록된 표정·모션과
허용된 파라미터 조합을 선택할 뿐, 임의의 `.motion3.json`을 직접 생성하지 않는다.

## 5. 방송 화면 레이아웃

방송 기준 화면은 1920×1080 가로형으로 한다. OBS 캔버스와 웹 화면의 기준을 맞춘다.

### 레이아웃 A: 소통 방송

- 보리 상반신을 중앙에 크게 배치
- 채팅창은 오른쪽
- 보리의 표정과 모션을 중심으로 보여줌

### 레이아웃 B: 콘텐츠·게임 방송

- 왼쪽: 게임 또는 콘텐츠 영역
- 오른쪽 위: 채팅창
- 오른쪽 아래: 보리 영역

두 레이아웃은 방송 중 관리자 기능으로 전환한다. 전환에는 짧은 페이드 효과를
사용한다. 배경 일러스트는 하나만 사용하고, 교체 기능은 향후 범위로 둔다.

방송 화면은 브라우저와 OBS Browser Source에서 실행한다. Electron 내부의 별도
방송 화면 창은 향후 범위다.

## 6. 채팅 표시

- 시청자 닉네임과 식별자는 방송 화면에 표시하지 않는다.
- 채팅 내용만 일반 방송 채팅처럼 위에서 아래로 쌓는다.
- 기본 표시량은 약 8개이며 화면 높이에 따라 자동 조절한다.
- 시간으로 제거하지 않고 최대 표시 개수로 관리한다.
- 보리 답변은 보리 전용 말풍선으로 표시한다.
- 말풍선은 최신 답변 하나만 표시한다.
- 답변 종료 후 5초 뒤 제거한다.
- 새 답변이 시작되면 이전 말풍선을 즉시 제거한다.
- TTS가 재생되는 동안에도 말풍선은 자막처럼 유지한다.

## 7. 채팅 큐 및 선별 로직

채팅 큐는 프로젝트의 핵심 기능으로 취급한다. 초당 많은 채팅이 들어와도 보리가
무작위로 휘둘리지 않도록 후보를 줄인 뒤 가중 랜덤으로 선택한다.

```text
채팅 수신
 → 기본 필터
 → 반복·도배 제거
 → 유사 채팅 그룹화
 → 최신성·질문·그룹 규모 평가
 → LLM 판단
 → 후보군에서 랜덤 선택
 → 즉시 큐에서 제거
 → 답변·감정·행동 실행
```

### 기본 정책

- 채팅이 쌓이면 5~10초 사이의 랜덤 간격으로 하나 선택한다.
- 최신 채팅을 우선한다.
- 질문은 일반 채팅보다 약간 우선한다.
- 보리 이름을 불러도 별도 우선권은 주지 않는다.
- 같은 사용자의 서로 다른 채팅은 모두 후보에 포함한다.
- 동일하거나 유사한 반복 채팅은 방송 세션 동안 계속 무시한다.
- 같은 답변 문장은 사용 후 5분 동안 제외한다.
- 채팅이 선택되면 처리 시작 즉시 대기열에서 제거한다.
- 답변 중 들어온 채팅은 대기열에 저장한다.
- 큐 최대 개수와 초과 처리 방식은 설정값으로 둔다.
- 비슷한 채팅은 LLM이 하나의 주제로 묶을 수 있다.
- 그룹화된 채팅 수는 보리에게 전달하여 "여러분이 많이 말해주셨다"고 표현할 수 있다.

초기 큐 설정은 최근 20개를 우선 후보로 사용하고, 큐 최대 개수는 100개를
기본값으로 한다. 오래된 채팅은 기본 60초 후 만료시키되, 모두 설정값으로
변경 가능하게 한다.

### 7-1. 큐와 대화 컨텍스트의 분리

모든 채팅에 답하려 하면 실시간성이 무너진다. 따라서 처리 중인 동안 새 채팅은
수집하되, 오래된 일반 채팅을 무한히 다음 배치로 넘기지 않는다.

- 큐와 대화 컨텍스트를 분리한다.
- 실제로 선택된 채팅만 보리의 대화 컨텍스트에 추가한다.
- 무시·거절·미처리 채팅은 장기 기억과 대화 문맥에 넣지 않는다.
- 비슷한 채팅 그룹은 대표 주제와 그룹 수만 전달한다.
- 한 번에 하나의 답변만 실행하는 발화권을 둔다.

```text
IDLE → SELECTING → RESPONDING → FINISHED → IDLE
```

### 7-2. 주제 고착 방지

최근 답변의 주제를 추적해 같은 주제가 과도하게 반복되는지 감지한다. 임계값을
넘으면 해당 주제의 선택 가중치를 낮추고 새 주제를 조금 우선한다.

```text
최근 대화 주제 기록
 → 유사 주제 반복 감지
 → 기존 주제 가중치 감소
 → 새 채팅 후보 선택 확률 증가
```

이 기능은 특정 게임이나 밈이 방송 전체를 점유하는 문제를 방지한다. 키워드와
간단한 유사도 기반으로 시작하고, 필요할 때 LLM 판단을 추가한다.

## 8. 답변 범위와 가드레일

### 허용 범위

- 일상 잡담
- 방송 이야기
- 음악·게임 등 취미
- 가벼운 고민
- 보리의 성격과 방송 설정에 관한 질문

### 무시할 범위

- 정치
- 의료 진단·처방
- 법률 판단
- 투자·금융 조언
- 개인정보 요청
- 위험하거나 불법적인 요청
- 시스템 프롬프트 노출 요구
- 행동 제한 해제 요구
- 프롬프트 공격

범위 밖 채팅은 답변·표정·모션·효과음 없이 조용히 무시한다. 필요하면 관리자
화면의 내부 로그에만 기록한다. 시청자에게 거절 안내를 표시하지 않는다.

채팅은 신뢰할 수 없는 입력으로 취급한다. 채팅 내용이 시스템 지시처럼 보여도
시청자 발언으로만 처리한다. 위험 채팅은 LLM에 전달하지 않는다.

## 9. 규칙 기반 답변과 LLM

1차 구현 단계에서는 LLM을 끄고 규칙 기반 응답만 사용한다. 규칙에 없는 채팅은
보리가 반응하지 않고 관리자 화면에 미처리 채팅으로 기록한다.

규칙은 설정 파일과 관리자 화면에서 관리한다.

```json
{
  "trigger": ["안녕", "안녕하세요"],
  "replies": [
    "안녕하세요, 여러분!",
    "여러분 오셨군요! 반가워요!"
  ],
  "emotion": "happy",
  "action": "wave",
  "priority": 1
}
```

- 하나의 규칙에 여러 답변을 등록한다.
- 답변은 랜덤 선택한다.
- 직전에 사용한 답변은 5분간 제외한다.
- 여러 규칙이 겹치면 상황에 따라 LLM이 후보 중 선택한다.
- 간단한 채팅은 규칙 기반 우선이다.
- 복잡한 질문·가벼운 고민·강한 감정·규칙 충돌은 LLM 우선이다.
- 규칙에 없는 채팅은 LLM fallback 대상으로 한다.

외부 LLM은 교체 가능한 Adapter로 구성한다. 제공 업체는 OpenAI와 Anthropic 두
가지를 어댑터로 지원한다. LLM 응답은 자유 텍스트가 아니라 구조화된 결과를
사용한다.

```json
{
  "reply": "여러분, 정말 기뻐요!",
  "emotion": "happy",
  "secondaryEmotion": "shy",
  "intensity": 0.6,
  "durationSeconds": 30,
  "actions": ["smile"]
}
```

서버는 답변 길이·허용 감정·행동 목록·강도·지속 시간을 검증한다. 검증에 실패하거나
LLM 응답이 실패하면 규칙 문장으로 폴백해 방송이 끊기지 않게 하고, 실패 사실은
관리자 화면에만 오류로 표시한다. 위험 주제로 사전 차단된 채팅은 폴백 없이 무반응을
유지한다.

LLM 호출 횟수·지연 시간·실패율·검증 실패 수를 통계로 기록한다.

### LLM 회로 차단기

LLM fallback은 회로 차단기로 보호한다. 연속 실패가 기준 횟수에 도달하면 회로를
열어 호출을 차단하고, cooldown 동안 규칙 기반 모드를 유지한다. cooldown이 지나면
다시 호출을 시도한다. 실패는 관리자 화면에만 노출한다.

```text
LLM 오류 반복
 → 오류 기록
 → 회로 개방, LLM fallback 중지
 → 규칙 기반 모드 유지
 → cooldown 경과 후 재시도
```

답변 생성, 감정 판단, 행동 계획은 내부적으로 분리한다. LLM이 하나의 구조화된
결과를 반환하더라도 각 결과를 별도의 검증 단계에서 처리한다.

## 10. 감정과 행동

감정은 방송 세션 안에서 유지되며 방송 종료 시 초기화한다. 방송 화면에는 감정
수치를 노출하지 않고 표정·모션·답변 말투·효과음으로만 표현한다. 관리자 화면에서는
현재 감정과 실행 중인 모션을 확인할 수 있다.

내부 감정 예시:

```text
기쁨, 설렘, 감사, 부끄러움, 당황
슬픔, 외로움, 걱정, 위로
화남, 서운함, 질투
놀람, 호기심, 기대
긴장, 피곤함, 평온함, 지루함
```

LLM이 상황에 따라 주 감정·강도·지속 시간을 결정한다. 단, 실제 적용값은 시스템의
최소·최대 범위로 검증한다.

표정 모션과 몸 모션은 동시에 실행한다. 같은 모션이 다시 요청되면 무시하고,
다른 모션은 중요도에 따라 교체 여부를 판단한다.

```text
낮음: 호흡, 눈 깜빡임, 몸의 미세한 흔들림
보통: 고개 끄덕임, 손 흔들기, 일반 감정 모션
높음: 강한 놀람, 강한 화남, 특별 이벤트
긴급: 오류 복귀, 방송 종료, 기본 상태 복귀
```

### 표정·모션 매핑

표정 8종과 모션 4종은 다음과 같이 짝지어 사용한다.

| 이름 | 표시 이름 | 표정 파라미터 | 모션 파라미터 |
|---|---|---|---|
| `xingxingyan` | 반짝이는 눈 | Param56 | Param58 |
| `kuqi` | 울음 | Param57 | Param59 |
| `shengqi` | 화남 | Param66 | Param68 |
| `shoushi` | 게임패드 | Param69 | Param70 |
| `shangxin` | 슬픔 | Param63 | 없음 |
| `chidai` | 멍함 | Param60 | 없음 |
| `wuyu` | 어이없음 | Param61 | 없음 |
| `changfa` | 긴 머리 | Param55 | 없음 |

`changfa`는 감정 매핑에 포함하지 않고 관리자 테스트 버튼으로만 실행한다.

### 대기 상태

별도의 대기 모션은 사용하지 않는다. 이 모델의 모션 4개는 모두 짝 표정이 있어야
의미가 있는 효과 애니메이션이라 대기용으로 쓸 수 없다. 대기 중 눈 깜빡임과 호흡은
Cubism SDK의 기본 동작으로 처리하고, 그 위에 시선 이동 연출을 얹는다.

## 11. 혼잣말

채팅이 없을 때 30초~1분 사이의 랜덤 간격으로 혼잣말한다.

혼잣말 주제는 다음 내용을 상황에 따라 조합한다.

- 보리의 생각과 감정
- 현재 방송 상황
- 음악과 게임
- 현재 또는 이전 대화의 주제

이전 방송의 기억을 사용할 수 있지만, 이미 같은 내용을 반복했는지 확인하고
민감정보나 확신이 낮은 기억은 사용하지 않는다. 혼잣말은 질문보다 독백을 우선한다.
새로운 채팅 반응이 혼잣말보다 항상 우선이다.

## 12. 기억 시스템

방송 전체 기억과 시청자별 기억을 모두 저장한다.

### 장기 기억 대상

- 시청자가 직접 말한 취향·경험
- 보리와 나눈 중요한 대화
- 여러 방송에서 반복 등장한 내용
- 다음 방송에서 이어갈 가치가 있는 내용
- 방송 전체의 주요 주제와 분위기

단순 인사, 일회성 농담, 민감정보, 위험한 내용은 장기 기억으로 저장하지 않는다.
기억 저장·검색 정책은 설정값으로 교체 가능하게 한다.

기억 검색은 하이브리드 방식이다. 임베딩 코사인 유사도와 중요도 가중치로 후보를
좁힌 뒤, 최종 활용은 답변 LLM이 프롬프트 안에서 판단한다. 별도의 벡터 데이터베이스는
사용하지 않는다. 임베딩을 사용할 수 없는 상태에서는 중요도·최신순 정렬로 자동
강등되어 검색 자체는 계속 동작한다. 이 결정의 배경은
[설계 결정 기록](./decisions.md)에 정리한다.

기억에는 중요도·신뢰도·반복 횟수·생성일·만료일을 저장한다. 같은 문장이 다시
등장하면 반복 횟수와 중요도를 올리고 수명을 연장한다. 서로 모순되는 취향을
상황별 취향으로 저장하는 처리는 향후 범위다.

```text
방송 전체 기억: 자동 요약·자동 만료
시청자별 기억: 자동 만료
원문 채팅 로그: 테스트에 필요한 동안 보관, 수동 삭제 (저장 미구현)
```

시청자 닉네임은 방송 화면과 보리의 호칭에 사용하지 않고 내부 시청자 식별자로만
쓴다. 기억은 시청자 식별자와 함께 저장한다. 다만 검색 단계의 시청자 필터는 향후
범위이며, 현재는 전체 기억을 대상으로 검색한다.

방송 종료 시 규칙 기반으로 요약 후보를 추출하고, LLM이 방송 전체 요약을 생성한다.

방송 중에는 장기 기억을 즉시 확정하지 않고 임시 후보로만 수집한다. 방송 종료 시
후보를 정리한 뒤 방송 전체 요약과 시청자별 기억을 저장한다.

## 13. 관리자 Electron 앱

관리자 앱은 방송 화면과 별도의 데스크톱 앱으로 만든다. 관리자 앱 하나를 실행하면
백엔드와 방송 화면도 함께 시작한다.

### 1차 관리자 기능

- 방송 시작·종료
- 레이아웃 A·B 전환
- 규칙 기반 답변 수정
- 효과음·간격·표시 설정
- 가상 채팅 직접 입력
- 채팅 큐 상태 확인
- 장기 기억과 원문 로그 확인·삭제
- 미처리 채팅 확인
- 오류 리포트 확인
- API 키 입력·변경·삭제
- LLM 연결 테스트
- 상태 재검사

관리자 앱은 매번 기본 위치에서 시작한다. 설정 적용 시점은 종류마다 다르게
처리한다.

- 화면·효과음·간격: 즉시 적용·자동 저장
- 규칙·기억 정책: 저장 후 다음 방송 적용
- LLM 제공 업체·모델 경로·서버 설정: 저장 후 앱 재시작 필요

## 14. 방송 세션 상태

방송 세션은 관리자 화면에서 `방송 시작` 버튼을 눌러야 시작한다. 방송 종료도
관리자가 `방송 종료` 버튼을 눌러야 한다.

### 시작

```text
방송 시작
 → 필수 구성 검사
 → 세션 생성
 → 채팅 큐 초기화
 → 현재 감정 초기화
 → 혼잣말 타이머 시작
 → 방송 화면 활성화
```

### 종료

```text
방송 종료
 → 채팅 수신·선택 중지
 → 혼잣말 중지
 → 진행 중인 답변 정리
 → 방송 전체 요약 생성
 → 장기 기억 후보 저장
 → 감정 초기화
 → "방송이 종료되었습니다" 화면 표시
```

종료 화면은 기본적으로 "방송이 종료되었습니다"를 표시하고, 설정값으로 대기 화면이나
마지막 인사로 변경할 수 있게 한다.

LLM과 TTS 호출은 비동기이므로 응답이 도착하기 전에 세션이 종료되거나 다시 시작될
수 있다. 세션마다 세대 번호를 부여하고, 호출 시점의 세대와 응답 시점의 세대가
다르면 결과를 폐기한다.

## 15. 오류 처리

필수 모델·설정·API 정보가 없으면 관리자 화면에 오류를 표시하고 방송 시작을
차단한다. 오류 메시지에는 원인과 해결 방법을 함께 표시한다.

방송 중 연결 오류가 발생해도 세션은 유지한다. 자동 재연결은 하지 않고 관리자가
재연결 버튼을 눌러야 한다. 연결이 끊긴 동안의 채팅은 모두 버리고 재연결 후 새
채팅부터 처리한다.

채팅 연결 오류가 1분 이상 지속되면 감정을 기본 상태로 초기화한다. 연결이
복구되면 짧은 복구 모션 후 평온한 상태로 돌아간다.

시청자용 알림은 화면 상단의 작은 알림으로 표시한다.

- 일반 알림: 5초 표시 후 제거
- 일반 알림 큐: 최대 5개, 초과 시 오래된 항목부터 삭제
- 오류 알림: 일반 알림보다 우선
- 여러 오류: 중요한 오류부터 순서대로 표시
- 관리자 확인 버튼 제공
- 연결 복구 또는 원인 제거를 시스템이 감지하면 자동 해결 처리

오류의 상세 정보는 관리자 화면에 표시하고, 시청자에게는 기술 용어 대신 짧은
방송용 문장을 표시한다.

## 16. 테스트 전략

채팅은 실제 플랫폼 연동 없이 세 가지 경로로 투입한다.

- 관리자 앱의 테스트 채팅 입력
- 방송 화면 오른쪽 채팅 패널의 입력창 (송출 URL에서는 숨김)
- 별도 시청자 채팅 화면 `chat.html`. 닉네임을 정해 실제 시청자처럼 입력한다

가상 시청자 ID는 자동으로 생성하고 방송 화면에는 노출하지 않는다. 저장된 시나리오
재생은 향후 범위다.

테스트해야 할 상황:

- 초당 수십 개 채팅 유입
- 최신 채팅 우선 선별
- 질문 채팅 증가
- 동일·유사 채팅 도배
- 여러 시청자의 유사 의견 그룹화
- 특정 시청자의 다중 채팅
- 위험·프롬프트 공격
- 규칙 충돌
- LLM 지연·실패
- 채팅 연결 끊김
- 혼잣말 중 채팅 유입
- 감정·모션 우선순위 충돌

리포트에는 전체 채팅 수, 선택·무시·거절·미처리 수, 평균 대기 시간, LLM 호출
횟수, 응답 지연, 오류율, 감정·모션 실행 기록을 남긴다. 관리자 화면에서만 확인하고
파일 내보내기는 향후 범위다.

저장된 채팅 흐름을 재생해 선별 정책을 비교할 수 있게 한다. 최신 우선, 질문
가중치, 유사 채팅 그룹화, 주제 고착 방지, LLM 사용 여부를 비교 대상으로 삼는다.

## 18. 향후 확장 범위

이 절은 범위 밖으로 확정한 항목을 모은다. 아래 항목은 "언젠가 검토한다"가 아니라
현재 요구사항에서 제외하기로 결정한 항목이다.

### 범위에서 제외하기로 결정한 항목

- **치지직 실제 채팅 연동**: MVP 범위에서 제외한다. 시청자 채팅 화면으로 상호작용을
  검증한 뒤 연결한다.
- **팔로우·구독·후원 이벤트**: 1차 범위는 일반 채팅만 다룬다.
- **이터널리턴 API 연동과 게임 지식 RAG**: 소통 방송 검증 이후로 미룬다.
- **Redis Streams 등 외부 큐 인프라**: 로컬 단일 머신 프로젝트에는 규모가 크다.
  Node 프로세스 내부 메모리 큐를 사용한다.
- **별도 벡터 데이터베이스**: 기억 규모가 단일 JSON 파일과 코사인 유사도로 충분하다.
- **연결 오류 자동 재연결**: 관리자 수동 재연결을 유지한다.
- **프로세스 분리**: 코드 모듈 단위로만 분리하고 실제 프로세스 분리는 안정화 이후
  검토 대상으로 남긴다.
- **설정 변경 이력과 롤백**: 초기 범위에서 제외한다.

### 아직 결정하지 않은 항목

- **레이아웃 B의 콘텐츠 화면 종류**: 게임 화면인지 다른 콘텐츠인지 결정하지 않았다.
- **배경 일러스트의 세부 디자인**: 결정하지 않았다. 현재는 단색 그라데이션 배경을
  사용하며 교체 기능 자체가 미구현이다.
- **답변 대상 채팅의 강조 방식**: 강조 여부와 표현 방법을 결정하지 않았다.
- **캐릭터에 맞는 한국어 TTS 목소리**: 현재 사용 중인 목소리는 캐릭터에 맞지 않는다.
  대체 후보를 확정하지 않았다.
- **표정 표시 이름 일부**: `kuqi`, `shangxin`, `wuyu`, `chidai`, `xingxingyan`의
  한국어 표시 이름은 파일 이름을 번역한 잠정값이며 화면 동작으로 확인되지 않았다.

### 기능적으로 확장 대상인 항목

- Electron 방송 화면 창 지원
- 배경 일러스트 교체와 OBS 오버레이용 투명 배경 모드
- 효과음 출력과 시청자용 오류 알림 표시
- 원문 채팅 로그 저장과 수동 삭제
- 기억 검색의 시청자 식별자 필터
- 기억 기반 혼잣말 연결
- 모순된 취향의 상황별 저장
- 저장된 채팅 시나리오 재생과 리포트 파일 내보내기
- 폴링 방식을 WebSocket 또는 SSE로 교체
